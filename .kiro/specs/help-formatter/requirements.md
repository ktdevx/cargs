# Requirements Document

## Project Description (Input)

### 誰が困っているか
コマンドラインツールの利用者は、`--help` で使い方を知りたい。ツールの開発者（CLArgs を取り込む C のアプリケーション開発者）がヘルプを手で書くと、オプションを足したり変えたりするたびに文面がずれていく。サブコマンドごとのヘルプや、`--no-<name>` の表記、値の表示名を揃えるのも手間がかかる。

### 現状
command-schema が、コマンド、オプション、位置引数の定義と、説明文などの表示用の属性、それを読むインターフェースを用意している。文面を作るものはまだない。

### 何を変えるか
- 利用者は、スキーマの任意のコマンド（ルートでもサブコマンドでも）を指定して、そのヘルプを生成できる。
- ヘルプには、usage 行、説明、オプションの一覧（短い名前と長い名前、値の表示名、説明）、位置引数、サブコマンドの一覧が入る。
- 否定できるフラグ、カウント、必須、既定値、選択肢が、一貫した表記で示される。
- usage 行だけを生成することもできる（エラー表示に添えるため）。
- 出力先は利用者が決める。ライブラリは標準出力に勝手に書かない。
- 表示幅を指定でき、長い説明は折り返される。
- 同じスキーマからは、どの OS でも同じ文面が出る。

### 進め方
スキーマの読み取りインターフェースだけを使い、文面を組み立てる。解析はしないし、argv-parser を呼ばない。出力は、利用者が渡す書き込み関数（シンク）に流す。固定長のバッファへ書く使い方は、その上の薄い補助として用意する（`FILE *` 向けの補助は、要件の検討で外した）。整形の設定（表示幅、字下げなど）は、設定関数を足していく形にして、後から項目を足せるようにする。

### スコープ
- **対象**: コマンドを指定したヘルプの生成（usage、説明、オプション、位置引数、サブコマンド）／usage 行だけの生成／否定、カウント、必須、既定値、選択肢、値の表示名の表記／出力先の抽象（書き込み関数）と、固定長のバッファ向けの補助／表示幅の指定と折り返し、列の揃え／整形の設定
- **対象外**: argv の解析、`--help` の検出（argv-parser がふつうのフラグとして報告する）／`--help` が指定されたときに表示して終了する一連の動作（利用者のコード）／解析エラーのメッセージ（argv-parser）／多言語化、色付け、端末の幅の自動検出／環境変数名の表記（`roadmap.md` の Future boundaries）／man ページ、Markdown、シェル補完スクリプトの生成／利用者によるテンプレートの差し替え／スキーマの内部構造に直接触れること、表示用の属性の保持（command-schema）／プロセスの終了

### 制約
- C99。公開構造体を ABI にしない。
- メモリを確保するなら core-runtime のアロケータを通す。
- core-runtime が持つアロケータの設定のほかに、変更可能なグローバル状態を持たない。
- 文面は英語のみ。見出しなどの固定の語句もここに含まれる。
- 折り返しの幅は、まずバイト数または ASCII の文字数で数える。ASCII 以外の文字の表示幅の扱いは要件で確定する。
- 改行は `\n` で出力する。Windows での変換は出力先に任せる。
- 表示に必要な属性が足りなければ、こちらで別に持たず、command-schema 側に足す。
- 公開名は `roadmap.md` の Naming に従う（ライブラリ名 `clargs`、ヘッダ `<clargs/clargs.h>`、接頭辞 `clargs_` / `CLARGS_`）。

詳細は同じディレクトリの `brief.md` を参照。

## Introduction

このスペックは、CLArgs（ライブラリ名 `clargs`）で、command-schema のスキーマからヘルプと usage 行の文面を作る部分を定める。対象は、コマンドを指定したヘルプの生成、usage 行だけの生成、オプション・位置引数・サブコマンドの表記、折り返しと列の揃え、整形の設定、出力先の抽象と、固定長のバッファ向けの補助である。このスペックは、スキーマを定義せず、argv を解析せず、`--help` を見つけることも、プロセスを終了することもしない。

利用者は 2 種類いる。

- **ライブラリ利用者**: CLArgs を自分のプログラムに取り込む C のアプリケーション開発者。スキーマのコマンドと出力先を渡して、ヘルプまたは usage 行を出力する。
- **プログラムの利用者**: ライブラリ利用者が作ったプログラムを、コマンドラインから使う人。出力されたヘルプを読んで、使い方を知る。

現在は、command-schema が、スキーマの定義、検証、読み取りインターフェース、値型を用意し、argv-parser が解析を用意している。文面を作るものはまだない。背景と判断の経緯は同じディレクトリの `brief.md` と、`.kiro/steering/roadmap.md` を参照。

この文書では、次の用語を使う。

- **対象のコマンド**: ヘルプまたは usage 行を生成する対象として、利用者が指定したコマンド。ルートコマンドでもサブコマンドでもよい。
- **コマンドの経路**: ルートコマンドから対象のコマンドまでの、コマンドの名前を、空白 1 つで区切って並べたもの（`tool remote add`）。
- **見出し**: 一覧の 1 項目の左側に出す、その項目の書き方（`-o, --output <FILE>`、`<input>`、サブコマンドの名前）。
- **注記**: 説明文の後ろに `[` と `]` で囲んで添える補足（`[default: 8080]` など）。
- **桁**: 行の先頭からの位置と幅を数える単位。1 バイトを 1 桁と数える（要件 7）。

ヘルプは、次の形になる（既定の設定での例）。

```
Usage: tool [OPTIONS] --output <FILE> <input> [extra]...

Convert the input file.

Arguments:
  <input>              File to read
  [extra]...           More files to read

Options:
  -o, --output <FILE>  File to write [required]
  -f, --format <FMT>   Output format [choices: json, yaml] [default: json]
  -v, --verbose...     Print more messages
      --[no-]color     Colorize the output [default: on]
  -h, --help           Show this help
```

brief.md が「要件で確定する」とした点と、brief.md が決めていなかった表記は、次のとおりに決めた。

| 点 | 決定 | 要件 |
|---|---|---|
| ASCII 以外の文字の表示幅 | 考慮しない。幅は 1 バイトを 1 桁と数える。折り返しは ASCII の空白の位置でだけ行うので、複数バイトの文字が途中で切れることはない | 7 |
| 検証を済ませていないスキーマ | 前提条件の違反（プログラムの誤り）として扱う（argv-parser と同じ） | 1 |
| 親コマンドのオプション | サブコマンドのヘルプには載せない（argv-parser が、サブコマンドの後ろで親のオプションを受け付けないため） | 3 |
| セクションの順序 | usage、説明、`Commands:`、`Arguments:`、`Options:`。項目のないセクションは出さない | 1 |
| 否定できるフラグ | `--[no-]<name>`。初期の状態がオンのときだけ `[default: on]` を添える | 3、5 |
| カウント | 名前の直後に `...` を付ける（`-v, --verbose...`） | 3 |
| 値の表示名が設定されていないとき | 値型の名前を使う（`<string>`、`<integer>` など） | 3 |
| 必須、既定値、選択肢 | 説明文の後ろの注記 `[choices: a, b]`、`[default: x]`、`[required]` | 5 |
| 位置引数 | 必須 `<name>`、任意 `[name]`、可変個 `[name]...`、必須の可変個 `<name>...` | 4 |
| usage 行のオプション | 必須でないオプションはまとめて `[OPTIONS]`、必須のオプションは 1 つずつ書く | 2 |
| サブコマンドの一覧の説明 | 説明文の最初の行だけを載せる | 4 |
| 既定の設定 | 表示幅 80 桁、字下げ 2 桁、説明の列の上限 32 桁 | 8 |
| バッファ向けの補助 | 利用者が用意した固定長のバッファに書く。収まらなければ切り詰めて、必要な長さを知らせる | 10 |
| `FILE *` 向けの補助 | 用意しない（brief.md からの変更）。利用者は、`fwrite()` を呼ぶ書き込み関数を自分で書く。例を文書に載せる | 9、13 |

## Boundary Context

- **In scope**:
  - 対象のコマンドを指定したヘルプの生成（usage 行、説明、サブコマンドの一覧、位置引数の一覧、オプションの一覧）
  - usage 行だけの生成
  - 否定できるフラグ、カウント、値の表示名、必須、既定値、選択肢の表記
  - 表示幅に合わせた折り返しと、説明の列の揃え
  - 整形の設定（表示幅、字下げ、説明の列の上限）
  - 出力先の抽象（利用者が渡す書き込み関数）と、固定長のバッファ向けの補助
- **Out of scope**:
  - argv の解析、`--help` の検出（argv-parser が、ふつうのフラグとして報告する）
  - `--help` のようなオプションを自動でスキーマに足すこと。`--help` が指定されたときに表示して終了する一連の動作（ライブラリ利用者のコード）
  - 解析エラーのメッセージ（argv-parser）。エラーのメッセージと usage 行を 1 つの出力にまとめること（ライブラリ利用者のコード）
  - 多言語化、色付け、端末の幅の自動検出
  - ASCII 以外の文字の表示幅（全角、結合文字など）に合わせた折り返しと揃え
  - 環境変数名の表記（`roadmap.md` の Future boundaries）
  - man ページ、Markdown、シェル補完スクリプトの生成
  - 利用者によるテンプレートやセクションの見出しの差し替え、セクションの並べ替え
  - `FILE *` に直接出力する補助（利用者が、`fwrite()` を呼ぶ書き込み関数を書く）
  - オプションやサブコマンドをヘルプから隠すこと、オプションをグループに分けること
  - 説明文などの属性を保持すること（command-schema）
  - プロセスの終了、利用者が指定していない出力先への書き込み
- **Adjacent expectations**:
  - command-schema: このスペックは、スキーマを、command-schema の読み取りインターフェースだけで読み、書き換えない。表示に必要な属性が足りなければ、このスペックで別に持たず、command-schema に足す。
  - command-schema: 検証済みのスキーマで成り立つこと（サブコマンドと位置引数は 1 つのコマンドに併存しない、可変個の位置引数は最後に 1 つだけ、必須と既定値は併用されない、など）に頼る。
  - core-runtime: アロケータ、エラーコードの拡張規約、所有権と寿命の規約（`docs/ownership.md`）、前提条件の扱いに従う。このスペックはそれらを変更しない。
  - argv-parser: 互いに呼ばない。解析の結果から `--help` が指定されたことを読み取ってヘルプを出すこと、解析エラーのメッセージに usage 行を添えることは、ライブラリ利用者のコードが行う。
  - 環境変数の対応（`roadmap.md` の Future boundaries）: 初版では実装しないが、後から、既存の利用者のプログラムを壊さずに注記を足せる形を保つ。

## Requirements

### Requirement 1: ヘルプの生成

**Objective:** As a ライブラリ利用者, I want スキーマのコマンドを 1 つ指定して、そのコマンドのヘルプを生成すること, so that ルートコマンドでもサブコマンドでも、定義からずれないヘルプを、手で書かずに出せる

#### Acceptance Criteria

1. When 利用者が対象のコマンドと出力先を指定してヘルプの生成を求めたとき, the clargs ライブラリ shall 対象のコマンドのヘルプの文面を、その出力先へ出力し、成功を返す。
2. The clargs ライブラリ shall 対象のコマンドとして、ルートコマンドと、入れ子の深さにかかわらずどのサブコマンドも受け付ける。
3. The clargs ライブラリ shall ヘルプを、usage 行、対象のコマンドの説明文、サブコマンドの一覧、位置引数の一覧、オプションの一覧の順に出力する。
4. The clargs ライブラリ shall サブコマンドの一覧の前に `Commands:`、位置引数の一覧の前に `Arguments:`、オプションの一覧の前に `Options:` だけからなる行を、行頭から出力する。
5. While 対象のコマンドに説明文が設定されていない間, the clargs ライブラリ shall 説明文の部分を出力しない。
6. While 対象のコマンドが、サブコマンド、位置引数、またはオプションを 1 つも持たない間, the clargs ライブラリ shall その種類の一覧と、その前の行を出力しない。
7. The clargs ライブラリ shall usage 行、説明文、各一覧の間を、空の行 1 つで区切り、ヘルプの先頭と末尾には空の行を出力しない。
8. The clargs ライブラリ shall 一覧の項目を、スキーマに定義した順に、1 項目ずつ行を改めて出力する。
9. The clargs ライブラリ shall 対象のコマンドの説明文を、行頭から、要件 7 の折り返しの規則に従って出力する。
10. The clargs ライブラリ shall 検証を済ませていないスキーマに属するコマンドをヘルプまたは usage 行の生成に渡すことを、エラーコードで報告せず、生成の関数の前提条件の違反として扱う。

### Requirement 2: usage 行

**Objective:** As a プログラムの利用者, I want コマンドの書き方が 1 行にまとまっていること, so that 何をどの順に書けばよいかを、一覧を読む前につかめる

#### Acceptance Criteria

1. The clargs ライブラリ shall usage 行を、`Usage: ` に続けて、コマンドの経路、オプションの部分、位置引数の部分、サブコマンドの部分の順に、空白 1 つで区切って並べたものとする。
2. While 対象のコマンドが、必須でないオプション（フラグ、否定できるフラグ、カウント、必須に設定されていない値付きオプション）を 1 つ以上持つ間, the clargs ライブラリ shall オプションの部分の先頭に `[OPTIONS]` を出力する。
3. While 対象のコマンドが必須の値付きオプションを持つ間, the clargs ライブラリ shall オプションの部分に、必須のオプションのそれぞれを、定義した順に、`--<長い名前> <値の表示名>` の形（長い名前を持たなければ `-<短い名前> <値の表示名>` の形）で出力する。
4. The clargs ライブラリ shall 位置引数の部分に、対象のコマンドの位置引数のそれぞれを、定義した順に、位置引数の一覧の見出し（基準 4.1）と同じ表記で出力する。
5. While 対象のコマンドがサブコマンドを 1 つ以上持つ間, the clargs ライブラリ shall サブコマンドの部分として `[COMMAND]` を出力する。
6. While 対象のコマンドが、オプション、位置引数、サブコマンドを 1 つも持たない間, the clargs ライブラリ shall usage 行を、`Usage: ` とコマンドの経路だけにする。
7. When 利用者が対象のコマンドと出力先を指定して usage 行だけの生成を求めたとき, the clargs ライブラリ shall 同じ設定でのヘルプの usage 行と同じ文面だけを、その出力先へ出力し、成功を返す。
8. If usage 行が表示幅に収まらなかったら, the clargs ライブラリ shall usage 行を、並べた部分の区切りの位置で折り返し、続きの行を空白 7 桁（`Usage: ` の幅）で字下げする。
9. The clargs ライブラリ shall usage 行を折り返すとき、コマンドの経路、`[OPTIONS]`、必須のオプション 1 つ（名前と値の表示名）、位置引数 1 つ、`[COMMAND]` のそれぞれを、途中で分けない。

### Requirement 3: オプションの見出し

**Objective:** As a プログラムの利用者, I want オプションの名前と、値を取るか、否定できるか、繰り返せるかが、決まった書き方で示されること, so that オプションの種類を、説明を読まなくても見分けられる

#### Acceptance Criteria

1. The clargs ライブラリ shall 短い名前と長い名前の両方を持つオプションの見出しを、`-<短い名前>, --<長い名前>` の形で始める。
2. The clargs ライブラリ shall 短い名前だけを持つオプションの見出しを、`-<短い名前>` の形で始める。
3. The clargs ライブラリ shall 長い名前だけを持つオプションの見出しを、空白 4 桁に続く `--<長い名前>` の形で始め、長い名前の位置を、短い名前を持つオプションと揃える。
4. The clargs ライブラリ shall 否定できるフラグの見出しで、長い名前を `--[no-]<長い名前>` の形で表す。
5. The clargs ライブラリ shall カウントのオプションの見出しで、名前の直後に `...` を付ける。
6. The clargs ライブラリ shall 値付きオプションの見出しで、名前の後ろに、空白 1 つと、`<` と `>` で囲んだ値の表示名を付ける。
7. While 値付きオプションに値の表示名が設定されていない間, the clargs ライブラリ shall そのオプションの値型の名前を、値の表示名として使う。
8. The clargs ライブラリ shall オプションの一覧に、対象のコマンドに定義されたオプションだけを載せ、親のコマンドおよび子のコマンドのオプションを載せない。
9. The clargs ライブラリ shall 利用者がスキーマに定義したヘルプ用のオプション（`--help` など）を、ほかのオプションと同じ規則で一覧に載せ、スキーマに定義されていないオプションを一覧に足さない。

### Requirement 4: 位置引数とサブコマンドの見出し

**Objective:** As a プログラムの利用者, I want 位置引数が必須か任意か、いくつ書けるかと、使えるサブコマンドが一覧で分かること, so that 引数の並びと、次に調べるサブコマンドを、ヘルプだけで決められる

#### Acceptance Criteria

1. The clargs ライブラリ shall 位置引数の見出しを、個数の種類に応じて、必須は `<名前>`、任意は `[名前]`、可変個は `[名前]...`、必須の可変個は `<名前>...` の形で表す。
2. The clargs ライブラリ shall サブコマンドの見出しを、そのサブコマンドの名前とする。
3. The clargs ライブラリ shall サブコマンドの一覧に、対象のコマンドの直接の子であるサブコマンドだけを載せ、孫以下のサブコマンドを載せない。
4. The clargs ライブラリ shall サブコマンドの一覧の説明として、そのサブコマンドの説明文のうち、最初の改行より前の部分だけを使う。
5. The clargs ライブラリ shall 名前、値の表示名、値型の名前、既定値、選択肢、説明文の文字を、大文字と小文字の変換を含め、変換せずにそのまま出力する。

### Requirement 5: 注記

**Objective:** As a プログラムの利用者, I want 必須かどうか、指定しなかったときの値、書ける値の一覧が、説明と並んで示されること, so that 説明文に書かれていなくても、省略できるか、何を書けるかが分かる

#### Acceptance Criteria

1. While 値付きオプションまたは位置引数の値型が選択肢である間, the clargs ライブラリ shall その項目に、選択肢を定義した順に `, ` で区切って並べた注記 `[choices: <選択肢>, <選択肢>]` を添える。
2. While 値付きオプションまたは位置引数に既定値が設定されている間, the clargs ライブラリ shall その項目に、設定された既定値の文字列をそのまま使った注記 `[default: <既定値>]` を添える。
3. While 否定できるフラグの初期の状態がオンである間, the clargs ライブラリ shall その項目に注記 `[default: on]` を添える。
4. While 否定できるフラグの初期の状態がオフである間, the clargs ライブラリ shall その項目に既定値の注記を添えない。
5. While 値付きオプションが必須に設定されている間, the clargs ライブラリ shall その項目に注記 `[required]` を添える。
6. The clargs ライブラリ shall 位置引数が必須かどうかを、見出しの表記（基準 4.1）だけで表し、位置引数に `[required]` の注記を添えない。
7. The clargs ライブラリ shall 注記を、説明文の末尾に、空白 1 つで区切って続け、複数の注記を、選択肢、既定値、必須の順に、空白 1 つで区切って並べる。
8. While 注記を持つ項目に説明文が設定されていない間, the clargs ライブラリ shall 注記だけを、その項目の説明として出力する。
9. The clargs ライブラリ shall 注記を、説明文の続きとして、要件 7 の折り返しの規則に従って出力する。

### Requirement 6: 列の揃え

**Objective:** As a プログラムの利用者, I want 見出しと説明が、列を揃えて並んでいること, so that 一覧を縦に目で追って、目的の項目を見つけられる

#### Acceptance Criteria

1. The clargs ライブラリ shall 一覧の各項目を、設定された字下げの桁数の空白に続けて、見出しから始める。
2. The clargs ライブラリ shall 1 つのヘルプの中のすべての一覧（サブコマンド、位置引数、オプション）で、説明を同じ桁（説明の列）から始める。
3. The clargs ライブラリ shall 説明の列を、字下げ、そのヘルプで最も幅の広い見出しの幅、空白 2 桁の合計とする。ただし、その合計が説明の列の上限を超えるときは、説明の列を上限と同じにする。
4. The clargs ライブラリ shall 説明の列の上限を、設定された上限と、表示幅の半分（端数は切り捨て。表示幅に制限がないときは考慮しない）の、小さいほうとする。ただし、字下げに 2 を足した桁数を下回らないものとする。
5. When 見出しの後ろに空白を 2 桁以上置いて説明の列に届くとき, the clargs ライブラリ shall 見出しと同じ行に、説明の列から説明を出力する。
6. If 見出しが長く、見出しの後ろに空白を 2 桁置くと説明の列を超えるなら, the clargs ライブラリ shall 見出しだけの行を出力し、説明を、次の行の説明の列から出力する。
7. While 項目に説明文も注記もない間, the clargs ライブラリ shall その項目を、見出しだけの行として出力する。
8. When 説明が複数の行にわたるとき, the clargs ライブラリ shall 2 行目以降も、説明の列から出力する。

### Requirement 7: 折り返しと行の形

**Objective:** As a プログラムの利用者, I want 長い説明が、表示幅に合わせて語の切れ目で折り返されること, so that 端末の幅を超える行で、ヘルプが読みにくくならない

#### Acceptance Criteria

1. The clargs ライブラリ shall 行の幅と位置を、1 バイトを 1 桁として数え、ASCII 以外の文字の表示上の幅を考慮しない。
2. When 説明の行が表示幅を超えるとき, the clargs ライブラリ shall その行を、表示幅に収まる最も後ろの ASCII の空白の位置で折り返す。
3. The clargs ライブラリ shall ASCII の空白以外の位置で行を折り返さず、空白を含まないひと続きの文字の並び（語）を、途中で分けない。
4. If 1 つの語が、それだけで行の残りの幅に収まらなかったら, the clargs ライブラリ shall その語を、それだけの行として、表示幅を超えたまま出力する。
5. When 説明文に改行が含まれるとき, the clargs ライブラリ shall その位置で行を改め、続きを、同じ開始の桁から出力する。
6. The clargs ライブラリ shall 折り返した位置の空白を出力せず、行の途中にある空白は、設定されたとおりの個数で出力する。
7. The clargs ライブラリ shall どの行の末尾にも空白を出力せず、空の行を、改行だけの行とする。
8. While 表示幅が「制限なし」に設定されている間, the clargs ライブラリ shall 説明文に含まれる改行の位置以外で行を折り返さない。
9. The clargs ライブラリ shall 行の区切りとして `\n` だけを出力し、出力する文面を、`\n` で終える。
10. The clargs ライブラリ shall 見出し、注記の枠、セクションの名前、`Usage: ` などの固定の語句を、英語だけで出力する。

### Requirement 8: 整形の設定

**Objective:** As a ライブラリ利用者, I want 表示幅や字下げを、必要なものだけ指定して変えること, so that 出力先の幅や自分のプログラムの見た目に、ヘルプを合わせられる

#### Acceptance Criteria

1. When 利用者が整形の設定の生成を求めたとき, the clargs ライブラリ shall すべての項目が既定の値である設定を生成して返す。
2. The clargs ライブラリ shall 設定の項目として、表示幅、字下げ、説明の列の上限の 3 つを提供する。
3. The clargs ライブラリ shall 既定の値を、表示幅 80 桁、字下げ 2 桁、説明の列の上限 32 桁とする。
4. When 利用者が設定の項目に値を設定したとき, the clargs ライブラリ shall その設定を使う以後の生成に、その値を使う。
5. When 利用者が表示幅に 0 を設定したとき, the clargs ライブラリ shall 表示幅を「制限なし」として扱う。
6. When 利用者が、設定を指定せずに（設定が「ない」ことを表す値を渡して）生成を求めたとき, the clargs ライブラリ shall すべての項目に既定の値を使う。
7. The clargs ライブラリ shall ヘルプの生成と usage 行だけの生成で、同じ設定を使えるようにする。
8. The clargs ライブラリ shall 生成の操作で設定を変更せず、1 つの設定を、複数の生成に繰り返し使えるようにする。
9. When 利用者が設定の破棄を求めたとき, the clargs ライブラリ shall その設定のために確保したメモリをすべて解放する。
10. The clargs ライブラリ shall 設定を、既存の利用者のプログラムを再ビルドなしで動作させ続けたまま、後のバージョンで新しい項目を足せる形で提供する。
11. The clargs ライブラリ shall 表示幅を、利用者が設定した値だけから決め、端末の幅や環境変数を調べない。

### Requirement 9: 出力先

**Objective:** As a ライブラリ利用者, I want 文面を、自分が渡した書き込み関数で受け取ること, so that 標準出力、標準エラー出力、ログ、メモリ上のバッファなど、出力先を自分で決められる

#### Acceptance Criteria

1. The clargs ライブラリ shall 出力先を、利用者が渡す書き込み関数と、その関数にそのまま渡される利用者のデータの組として受け付ける。
2. When 生成が文面を出力するとき, the clargs ライブラリ shall 書き込み関数を、文面の一部とその長さを渡して、文面の先頭から順に呼び出す。
3. The clargs ライブラリ shall 書き込み関数に渡した部分を、呼び出した順につなげたものが、文面の全体と一致するようにする。
4. The clargs ライブラリ shall 文面をいくつの部分に分けて書き込み関数を呼び出すかを、定めない。
5. If 書き込み関数が失敗を報告したら, the clargs ライブラリ shall それ以後は書き込み関数を呼び出さずに生成を止め、書き込みの失敗を表すエラーコードを返す。
6. The clargs ライブラリ shall 利用者が渡した出力先以外（標準出力、標準エラー出力を含む）へ、何も書き込まない。
7. The clargs ライブラリ shall 生成の成功、失敗にかかわらず、プロセスを中断または終了させない。

### Requirement 10: 出力先の補助

**Objective:** As a ライブラリ利用者, I want 文面を文字列として受け取りたいときに、書き込み関数を自分で書かずに済むこと, so that メッセージに組み込む、テストで比べる、といった使い方を、1 回の呼び出しでできる

#### Acceptance Criteria

1. When 利用者が、自分で用意したバッファとその大きさを指定して、ヘルプまたは usage 行の生成を求めたとき, the clargs ライブラリ shall 文面をそのバッファに書き込み、終端のナル文字を付ける。
2. When バッファへの生成が成功したとき, the clargs ライブラリ shall 文面の全体の長さ（終端のナル文字を除く）を、文面がバッファに収まったかどうかにかかわらず、利用者に知らせる。
3. If 文面がバッファに収まらなかったら, the clargs ライブラリ shall バッファに収まる分だけを書き込んで終端のナル文字を付け、バッファの外に書き込まずに、成功を返す。
4. When 利用者がバッファの大きさに 0 を指定したとき, the clargs ライブラリ shall バッファに何も書き込まずに、文面の全体の長さを知らせる。
5. The clargs ライブラリ shall 補助を通した出力の文面を、同じ対象のコマンドと設定で書き込み関数に出力した文面と、同じにする。

### Requirement 11: 再現性

**Objective:** As a ライブラリ利用者, I want 同じスキーマと設定から、いつでもどこでも同じ文面が出ること, so that ヘルプを文字列として比べるテストを書け、環境によって見た目が変わらない

#### Acceptance Criteria

1. When 利用者が、同じ内容のスキーマ、同じ対象のコマンド、同じ設定で生成を繰り返し求めたとき, the clargs ライブラリ shall 毎回、バイト単位で同じ文面を出力する。
2. The clargs ライブラリ shall 文面を、Linux・macOS・Windows のいずれでも、静的ライブラリと動的ライブラリのどちらでも、バイト単位で同じにする。
3. The clargs ライブラリ shall 文面を、プログラムのロケールの設定、環境変数、端末の状態によって変えない。
4. The clargs ライブラリ shall 生成の操作で、スキーマを変更しない。
5. While スキーマと設定が変更されていない間, when 複数のスレッドが、同じスキーマと設定に対する生成を、それぞれの出力先へ同時に求めたとき, the clargs ライブラリ shall 利用者に同期を求めずに、それぞれの生成を正しく完了させる。
6. The CLArgs リポジトリ shall ヘルプと usage 行の文面を、期待する文字列とバイト単位で比べる自動のテストを持ち、対応するすべての環境の CI で実行する。

### Requirement 12: メモリ、失敗時の保証、エラーの報告

**Objective:** As a ライブラリ利用者, I want 生成が失敗しても、メモリが漏れず、失敗の種類がエラーコードで分かること, so that 失敗を検査するだけで、安全にプログラムを続行または終了できる

#### Acceptance Criteria

1. The clargs ライブラリ shall このスペックの範囲で確保するすべてのメモリを、ライブラリ全体に設定されたアロケータから確保し、関数の引数としてアロケータを受け取らない。
2. If 設定の生成、または文面の生成の途中でメモリ確保が失敗したら, the clargs ライブラリ shall メモリ確保の失敗を表すエラーコードを返し、その呼び出しの中で確保したメモリを、戻るまでにすべて解放する。
3. If 文面の生成が失敗したら, the clargs ライブラリ shall スキーマと設定を、呼び出しの前と同じ内容で、引き続き使える状態に保つ。
4. The clargs ライブラリ shall 文面の生成が失敗したとき、失敗までに出力先へ渡した文面の一部が、出力先に残りうることを、文書に記載する。
5. When 生成の呼び出しが戻ったとき, the clargs ライブラリ shall その呼び出しのために確保したメモリを 1 つも残さず、利用者が解放する必要のあるものを返さない。
6. When 利用者が、設定の破棄の関数に「オブジェクトがない」ことを表す値を渡したとき, the clargs ライブラリ shall 何もせずに戻る。
7. The clargs ライブラリ shall 書き込みの失敗を表すエラーコードを、core-runtime のエラーコードの拡張規約に従って、既存のエラーコードの値と意味を変えずに足し、固有の空でない英語の説明文を持たせる。
8. The clargs ライブラリ shall 書き込みの失敗を、メモリ確保の失敗および成功と区別できるエラーコードで報告する。
9. The clargs ライブラリ shall 呼び出し側のプログラムの誤りでしか起こらない条件（必須の引数に「ない」ことを表す値を渡す、検証を済ませていないスキーマを渡すなど）を、エラーコードで報告せず、関数の前提条件として扱い、公開関数ごとに前提条件を文書に記載する。
10. The clargs ライブラリ shall このスペックの範囲で、変更可能なグローバル状態を持たない。
11. The CLArgs リポジトリ shall 設定の生成と文面の生成の各関数について、メモリ確保の各回を順に失敗させても、メモリの漏れがなく、スキーマと設定が使用と破棄のできる状態に保たれることを、自動のテストで確かめる。

### Requirement 13: 公開インターフェースの互換性と独立性

**Objective:** As a ライブラリ利用者, I want ヘルプの生成の API が、後のバージョンでも壊れず、解析とは別に使えること, so that 動的ライブラリを差し替えても自分のプログラムをビルドし直さずに使い続けられ、ヘルプだけが必要な場面でも使える

#### Acceptance Criteria

1. The clargs ライブラリ shall 整形の設定を、中身を利用者に公開しないハンドルとして提供し、後のバージョンで機能を足しても、既存の利用者のプログラムを再ビルドなしで動作させ続けられるようにする。
2. The clargs ライブラリ shall このスペックが公開する関数、型、マクロのすべてを、`<clargs/clargs.h>` を取り込むだけで使えるようにする。
3. The clargs ライブラリ shall このスペックが公開する関数と型のすべてに接頭辞 `clargs_` を、マクロと列挙の定数のすべてに接頭辞 `CLARGS_` を付ける。
4. The clargs ライブラリ shall このスペックの範囲では、実行時に C 標準ライブラリ以外へ依存せず、C99 の範囲で、コンパイラ独自の拡張を使わずに実装される。
5. The clargs ライブラリ shall ヘルプと usage 行の生成を、argv の解析の機能および解析の結果に依存せずに使えるものとし、スキーマを、command-schema の読み取りインターフェースだけを通して読む。
6. The CLArgs リポジトリ shall このスペックの公開関数の使い方（ヘルプの生成、usage 行だけの生成、設定、書き込み関数と補助、標準出力に出す書き込み関数の例、解析の結果から `--help` を読み取ってヘルプを出す例、解析エラーに usage 行を添える例を含む）と、表記の規則、ASCII 以外の文字の幅を考慮しないという制限を、リポジトリ内の文書に記載する。
