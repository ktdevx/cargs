# Brief: help-formatter

## Problem

コマンドラインツールの利用者は、`--help` で使い方を知りたい。ツールの開発者がヘルプを手で書くと、オプションを足したり変えたりするたびに文面がずれていく。サブコマンドごとのヘルプや、`--no-<name>` の表記、値の表示名を揃えるのも手間がかかる。

## Current State

command-schema が、コマンド、オプション、位置引数の定義と、説明文などの表示用の属性、それを読むインターフェースを用意している。文面を作るものはまだない。

## Desired Outcome

- 利用者は、スキーマの任意のコマンド（ルートでもサブコマンドでも）を指定して、そのヘルプを生成できる。
- ヘルプには、usage 行、説明、オプションの一覧（短い名前と長い名前、値の表示名、説明）、位置引数、サブコマンドの一覧が入る。
- 否定できるフラグ、カウント、必須、既定値、選択肢が、一貫した表記で示される。
- usage 行だけを生成することもできる（エラー表示に添えるため）。
- 出力先は利用者が決める。ライブラリは標準出力に勝手に書かない。
- 表示幅を指定でき、長い説明は折り返される。
- 同じスキーマからは、どの OS でも同じ文面が出る。

## Approach

スキーマの読み取りインターフェースだけを使い、文面を組み立てる。解析はしないし、argv-parser を呼ばない。

出力は、利用者が渡す書き込み関数（シンク）に流す。バッファへ書く、`FILE *` へ書く、といった使い方は、その上の薄い補助として用意する。こうすると、出力先を決めるのは常に利用者になり、テストでは文面を文字列として比べられる。

整形の設定（表示幅、字下げなど）は、設定関数を足していく形にして、後から項目を足せるようにする。

## Scope

- **In**:
  - コマンドを指定したヘルプの生成（usage、説明、オプション、位置引数、サブコマンド）
  - usage 行だけの生成
  - 否定、カウント、必須、既定値、選択肢、値の表示名の表記
  - 出力先の抽象（書き込み関数）と、バッファ・`FILE *` 向けの補助
  - 表示幅の指定と折り返し、列の揃え
  - 整形の設定
- **Out**:
  - argv の解析、`--help` の検出（argv-parser がふつうのフラグとして報告する）
  - `--help` が指定されたときに表示して終了する、という一連の動作（利用者のコード）
  - 解析エラーのメッセージ（argv-parser）
  - 多言語化、色付け、端末の幅の自動検出
  - man ページ、Markdown、シェル補完スクリプトの生成
  - 利用者によるテンプレートの差し替え。将来の拡張とする

## Boundary Candidates

- 文面の組み立て（スキーマからセクションへ）
- 整形（折り返し、列の揃え）
- 出力先の抽象と補助

## Out of Boundary

- スキーマの内部構造に直接触れること（読み取りインターフェースだけを使う）
- 説明文などの属性を保持すること（command-schema）
- 解析や結果オブジェクトへの依存
- プロセスの終了

## Upstream / Downstream

- **Upstream**: command-schema（読み取りインターフェース、表示用の属性）、core-runtime（アロケータ、状態コード）
- **Downstream**: ライブラリの利用者。将来、ほかの形式（man ページ、補完スクリプト）を足すなら、同じ読み取りインターフェースの上の別スペックとする。

## Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**:
  - command-schema: 表示に必要な属性が足りなければ、こちらで別に持たず、command-schema 側に足す。
  - argv-parser: 互いに呼ばない。並行して進められる。

## Constraints

- C99。公開構造体を ABI にしない。
- メモリを確保するなら core-runtime のアロケータを通す。
- 変更可能なグローバル状態を持たない。
- 文面は英語のみ。見出しなどの固定の語句もここに含まれる。
- 折り返しの幅は、まずバイト数または ASCII の文字数で数える。ASCII 以外の文字の表示幅の扱いは要件で確定する。
- 改行は `\n` で出力する。Windows での変換は出力先に任せる。
- 公開名は `roadmap.md` の Naming に従う（ライブラリ名 `clargs`、ヘッダ `<clargs/clargs.h>`、接頭辞 `clargs_` / `CLARGS_`）。
