# Implementation Plan

新しいソースまたはテストを作るタスクは、ライブラリのソース一覧またはテストの登録に 1 行足す。ほかのタスクも、同じソース、公開ヘッダ、内部ヘッダ、テストに追記する。同じファイルを触るので、並行させず、番号の順に行う（`(P)` を付けていない）。公開関数の宣言は、その関数を実装するタスクの中で公開ヘッダに足す。宣言だけを先に足すと、動的の構成の export の確認が失敗する。どのタスクも、スキーマは command-schema の公開関数だけで読み、スキーマを変更せず、内部のメモリ関数だけで確保し、変更可能な `static` 変数を足さず、`<stdio.h>` を取り込まず、ロケールに左右される関数を使わず、環境変数を読まず、argv-parser のコードを取り込まない。

文面のテストは、スキーマを組み立てて検証し、テストの中の書き込み関数（固定長の領域に足していく関数）で文面を受け取り、期待する文字列と、長さと内容の両方で比べる。8 より後のテストは、バッファの補助を使ってもよい。7.1 より前のタスク（5.1、5.2、6.1）のテストは、既定の設定で「字下げ + 最も広い見出しの幅 + 2」が 32 以下になるスキーマで書く。説明の列の上限と、次の行に送る規則が 7.1 で入っても、期待する文面が変わらないようにするためである。

  - 既存のエラーコードのテストのうち、コードごとの値と説明文を確かめている箇所に、新しいコードの値（一覧の末尾）と説明文の確認を足す
  - 完了の目安: エラーコードのテストが、足したコードについても、値が一覧の末尾で、説明文が空でなく、ほかと異なることを確かめて通る。既存のコードの値は変わらない

- [ ] 2. 状態を持たない部品
- [x] 2.1 ヘルプの公開ヘッダを作り、桁を数えながら書き込み関数へ出す内部の部品を作る
  - ヘルプの公開ヘッダを新しく作り、入口のヘッダから取り込む。この時点で入れるのは、書き込み関数の型だけである。型のコメントに、設計の「書き込み関数の契約」のすべての点（渡す部分は終端されない、長さは 1 以上、先頭から順、分け方は決まっていない、渡した文字列はその呼び出しの間だけ有効、失敗を返したら以後は呼ばれない、書き込み関数の中からスキーマを変更または破棄してはならない）を書く
  - 書き込み関数と利用者のデータ、現在の桁、まだ出していない空白の数、失敗の記憶を持つ内部の部品を作る。文字列を書く、空白を覚える、指定の桁まで空白を覚える、改行する、現在の桁を読む、失敗したかを読む、の操作を持つ
  - 空白は、次に文字列を書くときにはじめて出力し、改行では捨てる。桁は 1 バイトを 1 桁として数え、覚えている空白も含める。改行は `\n` だけを出力し、桁を 0 に戻す
  - 書き込み関数が失敗を返したら、以後は書き込み関数を呼ばない。桁の計算は続ける。書き込み関数を長さ 0 で呼ばない
  - 書き込み関数なしで初期化すると、何も出力せず、桁だけを数える。確保をしない。スキーマのヘッダを取り込まない
  - 内部関数のテストを足す。設計の Testing Strategy の `out_test.c` の内容（桁の進み方、空白が次の文字まで出ないこと、改行で捨てられること、指定の桁までの空白の境界、失敗の後は呼ばれないこと、書き込み関数なしで桁だけが進むこと、長さ 0 の呼び出しがないこと）を確かめる
  - 完了の目安: 静的と動的の両方の構成で部品のテストが通り、動的の構成の export の確認が通る（このタスクは公開関数を足さない）。入口のヘッダだけを取り込む利用者のプログラムがビルドできる

- [ ] 2.2 1 つの文字列を折り返して書く内部関数を作る
  - 長さの付いた 1 つの文字列を、開始の桁と表示幅に合わせて、2.1 の部品に書く内部関数を作る。規則は、設計の Wrap の Postconditions の 1〜6 のとおりである
  - 語は、ASCII の空白と改行以外のバイトの並びである。語の途中では改行しない。出力行の最初の語は、収まらなくても書く
  - 文字列の末尾の改行は取り除き、残りが空なら何も書かない。文字列の中の改行では行を改め、続きを開始の桁から書く。空の論理行は改行だけの行になる
  - 折り返した位置の空白と行末の空白は出さない。行の途中の空白と、論理行の先頭の空白は、そのままの個数で出す
  - 表示幅が 0 なら、文字列の中の改行の位置以外で折り返さない。最後の行の改行は書かない。確保をしない
  - 内部関数のテストを足す。設計の Testing Strategy の `wrap_test.c` の内容（幅にちょうど収まる語と 1 バイト超える語、先頭の語が幅を超える場合、連続する空白、論理行の先頭と末尾の空白、改行、連続する改行、末尾の改行、空の文字列、幅 0、開始の桁が現在の桁より大きい場合）を、出力の文字列の比較で確かめる
  - 完了の目安: 静的と動的の両方の構成で折り返しのテストが通り、どの期待する文字列にも、行末の空白がない

- [ ] 3. 整形の設定

  - 生成は、すべての項目が既定の値の設定を返す。確保に失敗したら、メモリ確保の失敗を返し、出力先を空のポインタにする
  - 破棄は、空のポインタには何もしない。設定関数は失敗せず、上限を超える値を上限の値として保持する。表示幅の 0 は「制限なし」として保持する
  - 公開関数のコメントに、前提条件、既定の値、上限、設定関数を呼んでいる間はほかのスレッドがその設定を使えないことを書く

  - 完了の目安: 静的と動的の両方の構成で設定のテストが通り、動的の構成の export の確認が、このタスクで宣言した 5 つの関数だけを新しい公開関数として認める。設定の値が文面に効くことは、4.2 と 7.2 で確かめる

- [ ] 4. usage 行
- [ ] 4.1 usage 行だけを生成する公開関数を作る
  - 位置引数の見出し（必須、任意、可変個、必須の可変個の 4 つの表記）と、usage 行での必須のオプションの表記（長い名前があれば長い名前、なければ短い名前に、値の表示名を続ける）を、2.1 の部品に書く内部関数を作る。値の表示名が設定されていなければ、値型の名前を使う。スキーマの文字列は変換しない。個数の種類の知らない値は、必須として扱う

  - このタスクでは、項目の間は常に空白 1 つとし、折り返さない。usage 行を書く処理は、5.1 でヘルプからも呼べるように、内部の関数 1 つにまとめる

  - 公開 API のテストを新しく作る。設計の Testing Strategy の `help_usage_test.c` のうち、折り返し以外（`[OPTIONS]` の有無、必須のオプションの 2 つの表記、値の表示名の有無、4 種類の位置引数、`[COMMAND]`、何も持たないコマンド、2 段目のサブコマンドの経路、設定が空のポインタの場合）を、文面の比較で確かめる
  - 完了の目安: 静的と動的の両方の構成で usage 行のテストが通り、動的の構成の export の確認が、このタスクで宣言した関数を新しい公開関数として認める

- [ ] 4.2 usage 行を表示幅で折り返す
  - 2 つ目以降の項目について、桁だけを数える部品に項目を 1 回書いて幅を得て、「現在の桁 + 1 + 項目の幅」が表示幅を超えるなら、空白の代わりに、改行と空白 7 桁を置く。表示幅が 0 なら折り返さない
  - コマンドの経路、`[OPTIONS]`、必須のオプション 1 つ、位置引数 1 つ、`[COMMAND]` は、中に空白があっても途中で分けない。1 つの項目が幅を超えるときは、そのまま出す

  - 完了の目安: 静的と動的の両方の構成で usage 行のテストが通り、設定した表示幅が usage 行に効くことが、文面の比較で確かめられている

- [ ] 5. ヘルプの構成と見出し
- [ ] 5.1 ヘルプを生成する公開関数を作り、説明、サブコマンド、位置引数の一覧を出す
  - ヘルプを生成する公開関数を作る。前提条件、設定の扱い、書き込みの失敗の返し方は、4.1 と同じである。4.1 の内部の関数で usage 行を書く

  - `Commands:` と `Arguments:` の一覧を、この順に、項目が 1 つ以上あるものだけ出す。それぞれ、空の行、名前だけの行、項目の順である。項目は定義した順に、字下げ、見出し、説明の順に書く。サブコマンドの見出しは名前で、直接の子だけを載せ、説明は説明文の最初の改行の手前までとする。位置引数の説明は、説明文の全体である
  - 説明の列は、すべての一覧の見出しの幅の最大から、「字下げ + 最大の幅 + 2」として 1 回だけ計算する（上限と、次の行に送る規則は 7.1 で入れる）。見出しの幅は、桁だけを数える部品に見出しを書いて得る。説明のない項目は、見出しだけの行にする
  - 対象のコマンドの説明文と項目の説明は、解決した設定の表示幅で折り返す。項目の字下げは設定の字下げを使い、項目の説明は説明の列から書く。設定の値を文面に使う処理は、このタスクで入れる（5.2 と 6.1 は、同じ処理に項目と注記を足すだけである）

  - 公開 API のテストを新しく作る。設計の Testing Strategy の `help_test.c` のうち、オプションに関わらないもの: 説明とサブコマンドを持つルートコマンドの全体、位置引数を持つ 2 段目のサブコマンドの全体、説明のないコマンド、何も持たないコマンド、空の行の数、定義した順、孫のサブコマンドが出ないこと、サブコマンドの説明が最初の行だけになること、空の文字列の説明文が出ないこと。同じ入力で 2 回生成した文面が一致し、生成の前後でスキーマの読み取りの結果と検証済みの状態が変わらないこと。usage 行だけの生成の文面が、ヘルプの先頭と一致すること
  - 完了の目安: 静的と動的の両方の構成でヘルプのテストが通り、動的の構成の export の確認が、このタスクで宣言した関数を新しい公開関数として認める

  - 完了の目安: 静的と動的の両方の構成で見出しのテストが通り、テスト用アロケータの未解放の個数と契約違反の回数が、生成の後に 0 である
