# Implementation Plan

新しいソースまたはテストを作るタスクは、ライブラリのソース一覧またはテストの登録に 1 行足す。ほかのタスクも、同じソース、公開ヘッダ、内部ヘッダ、テストに追記する。同じファイルを触るので、並行させず、番号の順に行う（`(P)` を付けていない）。公開関数の宣言は、その関数を実装するタスクの中で公開ヘッダに足す。宣言だけを先に足すと、動的の構成の export の確認が失敗する。どのタスクも、スキーマは command-schema の公開関数だけで読み、内部のメモリ関数だけで確保し、変更可能な `static` 変数を足さず、標準出力と標準エラーに書かず、環境変数を読まない。

  - 完了の目安: 既存のエラーコードのテストが、足したコードについても、説明文が空でなく、ほかと異なることを確かめて通る。既存のコードの値は変わらない
  - _Requirements: 11.11_

- [x] 2. 状態を持たない部品
- [x] 2.1 要素の形を分類する内部関数を作る
  - 要素 1 つを、オプションではない要素、長いオプション、短いオプションの束、終端の 4 つに分類する内部関数を作る。単独の `-`、空の文字列、`-` で始まらない要素は、オプションではない要素である。`--` に 1 文字以上が続けば長いオプション、`--` だけなら終端、`-` に `-` でない文字が続けば束である
  - 「`-` の直後が数字、または `-` の直後が `.` と数字」という負の数の形を判定する内部関数を作る。スキーマは見ない
  - 長いオプションの要素を、最初の `=` の手前までの名前（位置と長さ）と、`=` の直後の値（`=` がなければ「ない」）に分ける内部関数を作る
  - 文字の判定は ASCII の範囲の比較で書く。確保をしない
  - 内部関数のテストを足す。設計の Testing Strategy の `lex_test.c` の入力（`""`、`-`、`--`、`---`、`--x`、`--=x`、`-x`、`-xyz`、`-1`、`-.5`、`-.`、`-1x`、`x`、`x-y`、`=` が 0 個、1 個、2 個、空の値）を確かめる
  - 完了の目安: 静的と動的の両方の構成で分類のテストが通り、動的の構成でこれらの関数が export されない
  - _Boundary: Lex_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 3.1_

- [x] 2.2 ワイド文字列を UTF-8 に変換する内部関数を作る
  - ワイド文字列の UTF-8 での長さを数える内部関数と、呼び出し側が用意した領域に UTF-8 を書く内部関数を作る。確保をしない。2 つの関数は、同じ入力に同じバイト数を数える
  - ワイド文字が 16 ビットの環境では UTF-16 として読み、上位と下位のサロゲートの組を 1 つの符号位置にする。それより広い環境では UTF-32 として読む。環境の区別は、ワイド文字の最大値を前処理で比べて行う
  - 変換できない単位（UTF-16 では対になっていないサロゲート。UTF-32 では負の値、サロゲートの範囲の値、U+10FFFF を超える値）は U+FFFD に置き換え、長さを数える関数が「不正な並びがあった」ことを返す
  - OS の API、ロケールに左右される標準の変換関数は使わない
  - 内部関数のテストを足す。1〜4 バイトになる符号位置の境界（U+007F、U+0080、U+07FF、U+0800、U+FFFF、U+10000、U+10FFFF）、空の文字列、変換できない単位の置き換え、長さと書いたバイト数の一致を確かめる。環境で違う入力は、同じ前処理の条件で分け、どの環境でもアサーションが 1 つ以上実行されるように書く
  - 完了の目安: 静的と動的の両方の構成で変換のテストが通り、確保関数の検査が通る
  - _Boundary: Utf8_
  - _Requirements: 12.2, 12.3, 12.4_

- [x] 2.3 解析の公開ヘッダを作り、解析エラーのメッセージを組み立てる内部関数を作る

  - 種類、出どころ、名前の接頭辞と名前（長さ付き）、値、値型の名前を受け取り、設計の Message の文面の表のとおりの英語の 1 行を、1 回の確保で作る内部関数を作る。長さを先に数えてから写す。標準の整形関数は使わない。改行も、接頭辞も、句点も付けない
  - 値の変換の失敗は、オプション、位置引数、既定値で文面を変える。埋め込む文字列は加工しない
  - 確保に失敗したら、メモリ確保の失敗を返し、出力先を空のポインタにする
  - 内部関数のテストを足す。文面の表の各行、名前の長さが終端より手前で切れる場合、確保の失敗を確かめる。テスト用アロケータを使い、未解放の個数と契約違反の回数が 0 であることを確かめる
  - 完了の目安: 静的と動的の両方の構成でメッセージのテストが通り、動的の構成の export の確認が通る（このタスクは公開関数を足さない）

- [x] 3. 結果
- [x] 3.1 結果の生成と破棄、引数の複製、選ばれたコマンドの並びを作る
  - 結果の不透明な型を公開ヘッダに足す。中身（設計の Logical Data Model の構造体の全部）と、設計の Result の内部関数の宣言の全部を、内部ヘッダに定義する。フィールドを直接読み書きするのは、結果のソースだけである
  - `char` の引数から結果を生成する内部関数を作る。引数の配列とすべての文字列を、バイトを検査も変換もせずに、1 回の確保で複製する。大きさの足し算のたびに桁あふれを検査し、あふれたらメモリ確保の失敗とする。引数が 0 個なら複製を確保しない。ルートコマンドを並びの先頭に加える
  - コマンドを並びに加える内部関数を作る。そのコマンドのオプションと位置引数の個数ぶんの枠を作る。個数が 0 の枠の配列は確保しない。フラグは「指定されていない」、カウントは 0、否定できるフラグはスキーマの初期の状態で、出どころを既定値として始める。値付きオプションと位置引数は、値なしで始める
  - 結果を破棄する公開関数を作る。空のポインタには何もしない。作りかけのどの時点の結果も破棄でき、スキーマと値型は変更も破棄もしない
  - 解析の成否、並びの個数、番号でのコマンド、最後のコマンドを読む公開関数と、複製した要素を番号で読む内部関数を作る
  - 生成または追加の途中で確保に失敗したら、その呼び出しの確保を残さない。生成の失敗では出力先を空のポインタにする
  - 内部関数のテストを新しく作る。内部関数で結果を組み立てて、公開の読み取りと破棄を確かめる。このタスクで確かめること: 引数が 0 個、1 個、複数の複製と、複製の後に元の文字列を書き換えても影響しないこと。2 段の並びの個数と順序。空のポインタの破棄。破棄の後に未解放の個数と契約違反の回数が 0 であること
  - 完了の目安: 静的と動的の両方の構成で結果のテストが通り、動的の構成の export の確認が、このタスクで宣言した公開関数だけを新しい公開関数として認める

  - 3.1 の内部関数のテストに追記する。確かめること: 枠の初期の値と出どころ。フラグを 2 回記録しても「指定された」であること。カウントの回数。否定できるフラグが最後の記録の状態になること。並びに属さないコマンドのオプションの読み取り

- [x] 3.3 値の変換、保持、置き換え、読み取りを作る
  - 値付きオプションの値を記録する内部関数と、位置引数の値を記録する内部関数を作る。値 1 つごとに、値型の値の大きさの領域を確保し、文字列を加工せずに値型の変換に渡す。組み込みと利用者定義を区別しない。成功したら、枠に値と出どころを入れる
  - 値付きオプションに 2 回目の値が来たら、新しい領域に変換し、成功したら古い値を後始末して領域を解放し、新しい値に替える。失敗したら古い値を残す。位置引数は、値を並びの末尾に足す
  - 変換が成功以外を返したときは、値の領域を解放する。メモリ確保の失敗なら、そのまま返す。それ以外の失敗の記録は 3.4 で足すので、このタスクでは、解析エラーを表すエラーコードを返すところまでにする
  - 破棄を、保持しているすべての値を、値型の後始末でちょうど 1 回ずつ後始末してから領域を解放するように直す
  - 値付きオプションの読み取り（文字列、整数、浮動小数、選択肢の番号、値の領域）と、位置引数の読み取り（個数、出どころ、番号を指定した同じ 5 つ）の公開関数を作る。値がない、番号が個数以上、並びに属さないコマンドのもの、のどれでも、値がないことを返し、出力先を変えない。型の付いた読み取りは、値型の種類が合うことを前提条件とする
  - 3.1 の内部関数のテストに追記する。確かめること: 5 種類の値型（文字列、整数、浮動小数、選択肢、利用者定義）の値の読み取りと、型の付いた読み取りと値の領域が同じ値であること。置き換えで古い値が 1 回だけ後始末されること。変換の失敗で古い値が残ること。位置引数の値の順序と個数。破棄の後に、利用者定義の値型の後始末の回数が、成功した変換の回数に等しいこと。値のない場合の読み取り
  - 完了の目安: 静的と動的の両方の構成で結果のテストが通り、未解放の個数と契約違反の回数が 0 である
  - _Requirements: 5.4, 8.1, 8.2, 8.3, 8.5, 8.7, 10.3, 10.5, 10.6, 10.7, 10.8, 10.9, 10.15_

- [x] 3.4 解析エラーの記録と読み取り、既定値の取り消しを作る
  - 解析エラーを記録する内部関数を作る。種類、位置（出どころと要素の番号）、問題の要素、値、現在のコマンド、関係するオプションまたは位置引数、束の中の 1 文字を結果に書き、2.3 の関数でメッセージを組み立てて結果に持たせ、結果を「解析エラー」にして、解析エラーを表すエラーコードを返す。メッセージの確保に失敗したら、メモリ確保の失敗を返す
  - メッセージに埋め込む名前は、呼び出し側が渡した「書かれた形」（接頭辞と名前）を使う。値の変換の失敗では、値型の名前と、オプションか位置引数かの別も渡す
  - 3.3 の値の記録を、変換が入力の不正、またはそのほかのコード（成功でも、メモリ確保の失敗でもないもの）を返したときに、値の変換の失敗をこの関数で記録するように直す
  - 解析エラーの情報を読む公開関数（種類、メッセージ、問題の要素、値、位置の出どころ、要素の番号、現在のコマンド、オプション、位置引数、束の中の 1 文字）を作る。成功した結果と、エラーにその情報がない場合は、設計のとおり「ない」ことを表す値を返す。返す文字列は、結果が破棄されるまで有効である
  - 適用した既定値（出どころが既定値の、値付きオプションと位置引数の値）をすべて後始末して、値なしに戻す内部関数を作る。フラグ、カウント、否定できるフラグには触れない
  - 破棄を、メッセージも解放するように直す
  - 3.1 の内部関数のテストに追記する。確かめること: 記録した情報がそのまま読めること。記録の前と、成功した結果での読み取り。変換の失敗（不正、そのほかのコード）が値の変換の失敗として記録され、メモリ確保の失敗は記録されないこと。既定値の取り消しの後、値がなく、後始末が 1 回ずつであること。メッセージの確保の失敗
  - 完了の目安: 静的と動的の両方の構成で結果のテストが通り、動的の構成の export の確認が通る

- [ ] 4. 解析
- [x] 4.1 解析の入口と、長いオプションの照合を作る
  - `char` の argv を受け取る解析の公開関数を作る。引数の型は、`main` の argv をキャストなしで渡せる形にする。前提条件（ルートと出力先が空のポインタでない、ルートコマンドである、スキーマが検証済みである、argc が 0 以上、argv の要素が空のポインタでない）を `assert` で検査する
  - 結果を生成し、先頭の要素（プログラム名）を除いて、要素を先頭から順に 1 回ずつ走査する。走査の状態（現在のコマンド、要素の番号、終端を過ぎたか、位置引数のカーソル、数字の短い名前があるか）は、関数の中の自動変数に持つ。要素がなければ、何もせずに成功の結果を返す
  - 戻り値と出力先を、設計の表のとおりにする。成功と解析エラーでは結果を渡す。走査の途中でメモリ確保の失敗が返ったら、結果を破棄し、出力先を空のポインタにして返す。解析エラーが返ったら、走査をやめて結果を渡す
  - 長いオプションを照合する。2.1 の関数で名前と値に分け、現在のコマンドだけを検索する。長い名前で一致したら、フラグとカウントを記録し、否定できるフラグをオンにする。否定名で一致したら、オフにする。一致しなければ、未知のオプションの解析エラーとする
  - 値付きオプションは、`=` があればその直後を値にする（空でもよい）。なければ、次の要素を、内容にかかわらず値として取り込み、走査の位置を 1 つ進める。次の要素がなければ、値の不足の解析エラーとする。値を取らないオプションに `=` で値が付いていたら、その解析エラーとする。値の変換の失敗の問題の要素と番号は、値を含む要素のものにする（`--num x` では `x` の要素、`--num=x` ではその要素）。メッセージの名前は、書かれた形（`--` と名前。否定名で書かれたら否定名）にする
  - このタスクでは、短いオプションの束、オプションではない要素、終端は、まだ扱わず、読み飛ばす（4.2、4.3、4.4 で足す）。値の解決も、まだ呼ばない（5.1 で足す）
  - 公開 API のテストを新しく作る。確かめること: argc が 0 と 1 での結果。`--name`、`--name=value`、`--name value`、`--name=`、`--name=a=b`、`--no-name`、大文字と小文字の違い、前方一致が未知になること。`--name -x` と `--name --` が値になること。フラグ 2 回、カウント、`--color --no-color` と逆順、`--out a --out b`、`--num x --num 5` の解析エラー。同じスキーマで 2 回解析して同じ結果になること。解析の後に argv の文字列を書き換えても、結果の文字列が変わらないこと。このタスクのテストは、既定値と必須に頼らない
  - 完了の目安: 静的と動的の両方の構成でオプションの解析のテストが通り、動的の構成の export の確認が通る
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.7, 2.8, 2.9, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8, 3.9, 3.10, 5.1, 5.2, 5.3, 5.4, 5.5, 10.1, 10.10, 11.1, 13.2, 13.3_

- [ ] 4.2 短いオプションの束と、負の数の規則を作る
  - 束の文字を、先頭から 1 文字ずつ、現在のコマンドの短い名前として照合する。フラグとカウントは記録して次の文字へ進み、否定できるフラグはオンにする。一致しない文字は、その文字を原因とする未知のオプションの解析エラーとする
  - 値付きオプションの文字の後ろに文字が残っていれば、残りの全体を、`=` や `-` で始まっていてもそのまま値にして、束の解釈を終える。残っていなければ、次の要素を、内容にかかわらず値として取り込む。次の要素がなければ、値の不足の解析エラーとする

## Implementation Notes

- 3.3: 値の変換の失敗（メモリ確保の失敗を除く）は、`src/result.c` の `conversion_failure()` の 1 か所で `CLARGS_ERROR_INVALID_COMMAND_LINE` を返している。3.4 は、ここを解析エラーの記録に置き換える。`tests/internal/result_test.c` の `destroy_releases_every_value_once`、`positional_values_are_kept_in_their_order`、`positional_default_value_has_the_source_default`、`failed_conversion_keeps_the_value_of_an_option` は、1 つの結果で変換の失敗を 2 回以上起こすか、失敗の後も記録を続ける。解析エラーの記録は結果 1 つにつき 1 回なので、3.4 でこれらのテストを組み替える。
- 3.4: `clargs_result_fail()` は、結果 1 つにつき 1 回だけ呼ぶ（2 回目は `assert` で止まる）。`failure->command` は必ず渡す。出どころがコマンドラインなら、`where.index` は argc より小さい。出どころがコマンドラインでないとき（必須の不足、既定値）は、`where.index` を 0、`where.short_name` を `'\0'` にして渡す（記録はそのまま読み取りに出る。設計の「解析エラーの情報」の表を守るのは呼び出し側である）。`where.name_prefix` は `NULL` でもよい（`""` として読む）。メッセージの確保に失敗したときは、何も記録されず、`CLARGS_ERROR_OUT_OF_MEMORY` が返る。
- 4.1: `src/parse.c` の走査は `scan_arguments()` の `switch`（字句の種類）で、まだ扱わない種類は読み飛ばしている。オプションの記録は `record_option()` にまとめてあり、次の要素を値に取り込むときに `where->index` を値の要素に替える。束（4.2）からも同じ関数を呼ぶ。結果の生成の後は `parse_result()` に合流するので、値の解決（5.1）とワイド文字の入口（6.1）はここに足す。argv の各要素が `NULL` でないことは、`clargs_result_create()` の `assert` が検査する。公開ヘッダの `clargs_parse()` のコメントは、長いオプションまでしか書いていない。4.2〜5.1 は、足した書き方と値の解決をコメントに追記する。
