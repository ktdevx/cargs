# Requirements Document

## Project Description (Input)
### Problem

C のアプリケーション開発者は、`main` が受け取った argv を、定義したスキーマに当てはめて、型の付いた値として取り出したい。`-abc` の束ね、`-vvv`、`--name=value`、`--no-<name>`、`--` 終端、サブコマンドの切り替えを自分で書くと、細かな場合分けで誤りやすい。エラーのときに、どの引数がなぜ駄目だったのかを利用者に伝えるのも手間がかかる。

Windows では、`main` の `char` の argv は環境のコードページで渡され、ASCII 以外の文字が失われることがある。正しく受け取るには `wmain` のワイド文字の argv を扱う必要がある。

### Current State

command-schema が、コマンド、オプション、位置引数、値型の定義と、それを読むインターフェースを用意している。argv を読むものはまだない。

### Desired Outcome

- 利用者は、スキーマと argv を渡して解析し、結果オブジェクトを受け取れる。
- 次の書き方を解析できる。
  - 短いオプション: `-v`、束ね `-abc`、カウント `-vvv`、値 `-o value` と `-ovalue`
  - 長いオプション: `--name`、値 `--name value` と `--name=value`、否定 `--no-<name>`
  - `--` 以降はすべて位置引数
  - 位置引数
  - サブコマンド（入れ子も）。選ばれたサブコマンドの定義に切り替えて解析を続ける
- 結果から、フラグの真偽、カウントの回数、型の付いた値、位置引数、選ばれたサブコマンドの並びを取り出せる。指定されたのか既定値なのかも区別できる。
- 解析エラー（未知のオプション、値の不足、値の変換の失敗、必須の不足、余分な位置引数など）は、種類、問題の引数、関係するオプションを含む構造化された情報として返る。利用者に見せられる 1 行のメッセージも得られる。
- Windows で、ワイド文字の argv を渡して解析できる。
- 解析はスキーマを書き換えない。同じスキーマで何度でも解析できる。
- ライブラリは、プロセスを終了させず、標準出力や標準エラーに勝手に書かない。

### Approach

解析を 2 段に分ける。前段は、argv の 1 要素を「短いオプションの束」「長いオプション」「終端」「それ以外」に分類する字句の層で、スキーマを知らない。後段は、分類された要素をスキーマの読み取りインターフェースに照らして、オプションと値を対応づけ、サブコマンドで文脈を切り替える。値の変換は、command-schema の値型のインターフェースを呼ぶだけにする。

結果は、スキーマとは別の不透明なオブジェクトにし、利用者が破棄する。メモリは、core-runtime でライブラリ全体に設定されたアロケータから取る。

ワイド文字の argv は、入口で UTF-8 に変換してから同じ解析に流す。解析の本体は `char` の 1 系統だけにする。

### Scope

- **In**:
  - 解析の入口（スキーマ、argc、argv を受け取る）
  - 字句の分類と、スキーマとの照合
  - フラグ、否定、カウント、値付きオプション、位置引数、`--` 終端、サブコマンドの切り替え
  - 値型を通した変換と、変換の失敗の報告
  - 必須の検査、既定値の適用
  - 結果オブジェクトと参照 API、破棄
  - 構造化された解析エラーと、1 行のメッセージ
  - ワイド文字 argv の入口（Windows）
- **Out**:
  - スキーマの定義と検証（command-schema）
  - ヘルプや usage の文面（help-formatter）。`--help` はふつうのフラグとして報告するだけ
  - 長いオプション名の省略、レスポンスファイル（`@file`）
  - 環境変数からの値の補完。初版の対象外だが、後から「値の解決」の段の拡張として足す（`roadmap.md` の Future boundaries）
  - エラー時の候補の提案（"did you mean"）。将来の拡張とする
  - 解析後にコールバックでサブコマンドの処理を呼び出す仕組み。利用者が結果を見て分岐する

### Boundary Candidates

- 字句の層（argv の要素の分類。スキーマを知らない）
- 照合の層（スキーマとの対応づけ、サブコマンドの切り替え）
- 値の解決の層（照合の結果から、既定値の適用と必須の検査をして最終的な値を決める。将来、環境変数などの供給元を足す場所）
- 結果オブジェクトと参照 API
- 解析エラーの表現とメッセージ
- 入力の適応（ワイド文字 argv から UTF-8 へ）

### Out of Boundary

- スキーマを書き換えること、スキーマの内部構造に直接触れること
- 値の変換の実装（command-schema の値型が持つ）
- ヘルプの表示、プロセスの終了、出力先への書き込み
- アロケータとエラーコードの仕組み（core-runtime）

### Upstream / Downstream

- **Upstream**: command-schema（読み取りインターフェース、値型のインターフェース）、core-runtime（アロケータ、エラーコード、所有権の規約、テスト用アロケータ）
- **Downstream**: ライブラリの利用者。将来、候補の提案や低水準のイテレータを足すならここを拡張する。

### Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**:
  - command-schema: 値型と読み取りインターフェースの契約を共有する。足りない読み取り関数があれば、こちらで内部に手を入れず、command-schema 側に足す。
  - help-formatter: 互いに呼ばない。usage を添えたエラー表示は、利用者が両方の出力を組み合わせる。

### Constraints

- C99。公開構造体を ABI にしない。
- すべてのメモリ確保は core-runtime のアロケータを通す。確保の失敗はエラーとして返し、途中まで作ったものを漏らさない。
- core-runtime が持つアロケータの設定のほかに、変更可能なグローバル状態を持たない。
- 結果が argv の文字列を借りるかコピーするか、結果がスキーマより長生きしてよいかは、core-runtime の所有権の規約に沿って設計で決める。
- 次の点は要件で確定する。
  - オプションと位置引数の混在を許すか
  - 同じオプションを複数回指定したときの扱い（最後が勝つ、または蓄積する）
  - 親コマンドのオプションをサブコマンドの後ろに書けるか
  - 負の数（`-1`）と短いオプションの区別
  - 単独の `-` の扱い
- 環境変数の対応を後から非破壊で足せるようにする（`roadmap.md` の Future boundaries）。
  - 値の出どころは真偽値ではなく列挙型で返す（初版は「コマンドライン」と「既定値」の 2 値）。
  - 解析エラーの位置情報は、argv の位置だけに固定せず、出どころの種類を持てる形にする。
  - 環境を読むための差し込み口は初版では公開しない。パーサーの中で `getenv` を呼ばない。
- ワイド文字の入口を Windows 以外でも提供するかは設計で決める。
- メッセージは英語のみ。
- 公開名は `roadmap.md` の Naming に従う（ライブラリ名 `argx`、ヘッダ `<argx/argx.h>`、接頭辞 `argx_` / `ARGX_`）。

詳細は同じディレクトリの `brief.md` を参照。

## Introduction

このスペックは、ArgX（ライブラリ名 `argx`）で、argv を command-schema のスキーマに当てはめて解析する部分を定める。対象は、解析の入口、argv の書き方の解釈、値型を通した値の変換、既定値の適用と必須の検査、結果の参照、解析エラーの報告、ワイド文字の argv の受け付けである。このスペックは、スキーマを定義せず、ヘルプの文面も作らない。

利用者は 2 種類いる。

- **ライブラリ利用者**: ArgX を自分のプログラムに取り込む C のアプリケーション開発者。`main` が受け取った argv を解析に渡し、結果から値を取り出す。
- **プログラムの利用者**: ライブラリ利用者が作ったプログラムを、コマンドラインから使う人。このスペックが定める書き方で引数を書き、誤りがあればメッセージを読む。

現在は、command-schema が、スキーマの定義、検証、読み取りインターフェース、値型を用意している。argv を読むものはまだない。背景と判断の経緯は同じディレクトリの `brief.md` と、`.kiro/steering/roadmap.md` を参照。

この文書では、次の用語を使う。

- **要素**: argv の 1 つの文字列。
- **現在のコマンド**: 解析がその時点で定義を参照しているコマンド。解析の開始時はルートコマンドで、サブコマンドが選ばれるたびに、そのサブコマンドに替わる。
- **選ばれたコマンドの並び**: ルートコマンドから、最後に選ばれたサブコマンドまでの、コマンドの並び。サブコマンドが 1 つも選ばれなければ、ルートコマンドだけである。
- **定義要素**: オプションと位置引数の総称。
- **解析エラー**: プログラムの利用者が書いた引数が、スキーマに合わないこと。メモリ確保の失敗と、ライブラリ利用者のプログラムの誤りは含まない。

brief.md が「要件で確定する」とした点は、次のとおりに決めた。

| 点 | 決定 | 要件 |
|---|---|---|
| オプションと位置引数の混在 | 許す。`--` より後ろだけが、必ず位置引数になる | 6 |
| 同じオプションの複数回の指定 | 値付きオプションと否定できるフラグは、最後の指定が有効。カウントは回数を数える。値は蓄積しない | 5 |
| 親コマンドのオプションをサブコマンドの後ろに書けるか | 書けない。オプションは、現在のコマンドの定義だけから探す | 7 |
| 負の数と短いオプションの区別 | `-` の直後が数字（または `.` と数字）の要素は、現在のコマンドに数字の短い名前のオプションが 1 つもなければ、オプションとして扱わない | 2 |
| 単独の `-` | オプションではない、ふつうの文字列として扱う | 2 |
| 値を次の要素から取るとき、次の要素が `-` で始まる場合 | 内容にかかわらず値にする | 3、4 |
| 解析エラーが複数あるとき | 最初に見つけた 1 つだけを報告する | 11 |
| 検証を済ませていないスキーマ | 前提条件の違反（プログラムの誤り）として扱う | 1 |
| 解析エラーのときの結果 | エラーを見つけるまでに読んだ分を、結果から調べられる（`--help` を、必須の不足があっても読み取れる） | 10 |

## Boundary Context

- **In scope**:
  - 解析の入口（スキーマと、`main` が受け取った argc と argv を受け取る）
  - 要素の解釈（長いオプション、短いオプションとその束ね、`--` 終端、単独の `-`、負の数、位置引数、サブコマンドの名前）
  - フラグ、否定できるフラグ、カウント、値付きオプションの扱いと、複数回指定されたときの扱い
  - 値型を通した値の変換と、変換の失敗の報告
  - 既定値の適用と、必須の検査
  - 結果オブジェクト、その参照、破棄
  - 構造化された解析エラーと、1 行のメッセージ
  - ワイド文字の argv の受け付け（Windows）
- **Out of scope**:
  - スキーマの定義と検証、値型の変換そのもの（command-schema）
  - ヘルプや usage の文面。`--help` のようなオプションを特別に扱うこと（ふつうのフラグとして報告するだけである）
  - 長いオプション名の省略（前方一致）、レスポンスファイル（`@file`）
  - 複数の値を集めるオプション（リスト）
  - 親コマンドのオプションを、サブコマンドの後ろで受け付けること
  - 環境変数や設定ファイルからの値の補完。環境を読むこと
  - 解析エラーのときの候補の提案（"did you mean"）
  - 解析の後に、サブコマンドの処理をコールバックで呼び出すこと
  - メッセージの多言語化（メッセージは英語のみ）
  - アロケータとエラーコードの仕組みそのもの（core-runtime）
- **Adjacent expectations**:
  - command-schema: このスペックは、スキーマを、command-schema の読み取りインターフェースだけで読み、書き換えない。値の変換と後始末は、値型のインターフェースを通して求め、組み込みの値型と利用者定義の値型を区別しない。読み取りインターフェースに足りないものがあれば、スキーマの内部に触れず、command-schema に足す。
  - command-schema: 名前の規則（短い名前は ASCII の英字または数字の 1 文字、長い名前は 2 文字以上、サブコマンドと位置引数は 1 つのコマンドに併存しない、可変個の位置引数は最後に 1 つだけ、など）は、検証済みのスキーマで成り立っているものとして頼る。
  - core-runtime: アロケータ、エラーコードの拡張規約、所有権と寿命の規約（`docs/ownership.md`）、前提条件の扱いに従う。このスペックはそれらを変更しない。結果はスキーマより先に破棄する（`docs/ownership.md` の適用）。
  - help-formatter: 互いに呼ばない。`--help` が指定されたことを結果から読み取って文面を出すのは、ライブラリ利用者のコードである。
  - 環境変数の対応（`roadmap.md` の Future boundaries）: 初版では実装しないが、後から、既存の利用者のプログラムを壊さずに足せる形を保つ（要件 9、10、11）。

## Requirements

### Requirement 1: 解析の入口

**Objective:** As a ライブラリ利用者, I want 検証済みのスキーマと `main` が受け取った argv を渡して解析を求めること, so that 自分で argv を調べずに、結果かエラーのどちらかを受け取れる

#### Acceptance Criteria

1. When 利用者が、検証済みのスキーマのルートコマンドと、argc と argv を指定して解析を求めたとき, the argx ライブラリ shall argv をそのスキーマに当てはめて解析し、成功、解析エラー、メモリ確保の失敗のどれであったかを、エラーコードで返す。
2. The argx ライブラリ shall `main` が受け取った argc と argv を、利用者が加工せずにそのまま渡せるものとし、argv の先頭の要素をプログラム名として、解析の対象にしない。
3. When argv に、プログラム名のほかの要素が 1 つもない（argc が 0 の場合を含む）とき, the argx ライブラリ shall 何も指定されなかったコマンドラインとして解析する。
4. The argx ライブラリ shall 解析によって、スキーマ、値型、argv の配列、argv の文字列のいずれも変更しない。
5. When 利用者が、同じスキーマで解析を繰り返し求めたとき, the argx ライブラリ shall それぞれの解析を、前の解析の影響を受けずに行い、同じ argv には同じ結果を返す。
6. While スキーマが変更されていない間, when 複数のスレッドが同じスキーマで同時に解析を求めたとき, the argx ライブラリ shall 利用者に同期を求めずに、それぞれの解析を正しく完了させる。
7. The argx ライブラリ shall 検証を済ませていないスキーマ、およびルートコマンドでないコマンドを解析に渡すことを、エラーコードで報告せず、解析の関数の前提条件の違反として扱う。
8. The argx ライブラリ shall 解析のために、プロセスを終了させず、標準出力、標準エラー、そのほか利用者が指定していない出力先へ書き込まず、環境変数を読まない。

### Requirement 2: 要素の解釈

**Objective:** As a プログラムの利用者, I want 引数の 1 つ 1 つが、オプションなのか、そうでないのかが、決まった規則で判断されること, so that 負の数や `-` のような紛らわしい引数も、意図したとおりに渡せる

#### Acceptance Criteria

1. When 要素が、`--` に 1 文字以上が続く形であるとき, the argx ライブラリ shall その要素を長いオプションとして扱う。
2. When 要素が `--` だけであるとき, the argx ライブラリ shall その要素をオプションの終端として扱う。
3. When 要素が、`-` に、`-` でない文字が 1 文字以上続く形であるとき, the argx ライブラリ shall その要素を、短いオプションの束として扱う。ただし、基準 5 に当てはまる要素を除く。
4. When 要素が `-` だけであるとき, the argx ライブラリ shall その要素を、オプションではない要素として扱う。
5. When 要素が、`-` の直後に数字が続く形、または `-` の直後に `.` と数字が続く形であり、かつ現在のコマンドに、数字を短い名前とするオプションが 1 つも定義されていないとき, the argx ライブラリ shall その要素を、オプションではない要素として扱う。
6. When 要素が `-` で始まらないとき, the argx ライブラリ shall その要素を、空の文字列である場合を含めて、オプションではない要素として扱う。
7. While オプションの終端より後ろの要素を解析している間, the argx ライブラリ shall すべての要素を、`-` で始まるものを含めて、オプションではない要素として扱う。
8. The argx ライブラリ shall 要素を、argv の先頭から順に、1 回ずつ解釈する。
9. When 要素が、値付きオプションの値として取り込まれたとき, the argx ライブラリ shall その要素を、この要件の規則で解釈せず、値の文字列としてだけ扱う。

### Requirement 3: 長いオプション

**Objective:** As a プログラムの利用者, I want `--name`、`--name value`、`--name=value`、`--no-name` の書き方で長いオプションを指定すること, so that 広く使われている書き方のままで、プログラムにオプションを渡せる

#### Acceptance Criteria

1. When 長いオプションの要素を解釈するとき, the argx ライブラリ shall `--` の後ろから、最初の `=` の手前まで（`=` がなければ要素の終わりまで）を名前とし、最初の `=` より後ろを、その要素に付けられた値とする。
2. When 名前が、現在のコマンドのオプションの長い名前と完全に一致したとき, the argx ライブラリ shall そのオプションが指定されたものとして扱う。
3. When 名前が、現在のコマンドの否定できるフラグの否定名（`no-<name>`）と完全に一致したとき, the argx ライブラリ shall そのフラグが、オフとして指定されたものとして扱う。
4. When 否定できるフラグが、その長い名前で指定されたとき, the argx ライブラリ shall そのフラグが、オンとして指定されたものとして扱う。
5. The argx ライブラリ shall 長いオプションの名前を、大文字と小文字を区別して、完全に一致するものだけと対応づけ、名前の一部だけの指定（省略）を受け付けない。
6. If 名前が、現在のコマンドのどのオプションの長い名前とも否定名とも一致しなかったら, the argx ライブラリ shall 未知のオプションを表す解析エラーを報告する。
7. When 値付きオプションが、値を付けた形（`--name=value`）で指定されたとき, the argx ライブラリ shall `=` より後ろの文字列を、空の文字列である場合を含めて、そのオプションの値とする。
8. When 値付きオプションが、値を付けない形（`--name`）で指定されたとき, the argx ライブラリ shall 次の要素を、その内容にかかわらず（`-` で始まる要素、`--` を含めて）、そのオプションの値として取り込む。
9. If 値付きオプションが値を付けない形で指定され、次の要素がなかったら, the argx ライブラリ shall 値の不足を表す解析エラーを報告する。
10. If フラグ、否定できるフラグ、またはカウントが、値を付けた形（`--name=value`、`--no-name=value`）で指定されたら, the argx ライブラリ shall 値を取らないオプションに値が付けられたことを表す解析エラーを報告する。

### Requirement 4: 短いオプションと束ね

**Objective:** As a プログラムの利用者, I want `-v`、`-abc`、`-vvv`、`-o value`、`-ovalue` の書き方で短いオプションを指定すること, so that 短い書き方で、複数のオプションをまとめて渡せる

#### Acceptance Criteria

1. When 短いオプションの束の要素を解釈するとき, the argx ライブラリ shall `-` の後ろの文字を、先頭から 1 文字ずつ、現在のコマンドのオプションの短い名前として順に対応づける。
2. When 束の中の文字が、フラグ、否定できるフラグ、またはカウントの短い名前であるとき, the argx ライブラリ shall そのオプションが指定されたものとして扱い、束の次の文字へ進む。
3. When 否定できるフラグが、短い名前で指定されたとき, the argx ライブラリ shall そのフラグが、オンとして指定されたものとして扱う。
4. When 束の中の文字が値付きオプションの短い名前で、その後ろに文字が残っているとき, the argx ライブラリ shall 残りの文字列の全体を、`=` や `-` で始まる場合を含めてそのまま、そのオプションの値とし、束の解釈を終える。
5. When 束の中の文字が値付きオプションの短い名前で、その後ろに文字が残っていないとき, the argx ライブラリ shall 次の要素を、その内容にかかわらず（`-` で始まる要素、`--` を含めて）、そのオプションの値として取り込む。
6. If 束の最後の文字が値付きオプションの短い名前で、次の要素がなかったら, the argx ライブラリ shall 値の不足を表す解析エラーを報告する。
7. If 束の中の文字が、現在のコマンドのどのオプションの短い名前でもなかったら, the argx ライブラリ shall その文字を問題の名前とする、未知のオプションを表す解析エラーを報告する。
8. The argx ライブラリ shall 短い名前を、大文字と小文字を区別して対応づける。

### Requirement 5: 複数回の指定

**Objective:** As a プログラムの利用者, I want 同じオプションを何度か書いたときの結果が、種類ごとに決まっていること, so that `-vvv` で詳しさを上げたり、エイリアスで決めた値を後ろから上書きしたりできる

#### Acceptance Criteria

1. When フラグが 1 回以上指定されたとき, the argx ライブラリ shall 回数にかかわらず、そのフラグを「指定された」とする。
2. When カウントが指定されたとき, the argx ライブラリ shall 短い名前での指定と長い名前での指定を合わせた回数を、そのカウントの値とする。
3. When 否定できるフラグが、オンまたはオフとして 2 回以上指定されたとき, the argx ライブラリ shall argv で最も後ろにある指定の状態を、そのフラグの状態とする。
4. When 値付きオプションが 2 回以上指定されたとき, the argx ライブラリ shall argv で最も後ろにある指定の値を、そのオプションの値とし、前の指定の値を結果に残さない。
5. When 値付きオプションが 2 回以上指定されたとき, the argx ライブラリ shall それぞれの指定の値を、指定のたびに値型で変換し、どれか 1 つでも変換に失敗したら、解析エラーを報告する。

### Requirement 6: 位置引数とオプションの終端

**Objective:** As a プログラムの利用者, I want 位置引数を、オプションと混ぜて、定義された順に渡すこと, so that `tool input.txt -v output.txt` のように、思いついた順に引数を書ける

#### Acceptance Criteria

1. When サブコマンドを持たないコマンドが現在のコマンドである間に、オプションではない要素が現れたとき, the argx ライブラリ shall その要素を、現在のコマンドの位置引数の値として扱う。
2. The argx ライブラリ shall 位置引数の値を、現れた順に、定義した順の位置引数へ割り当て、必須と任意の位置引数には 1 個ずつ、可変個と必須の可変個の位置引数には残りのすべてを割り当てる。
3. The argx ライブラリ shall オプションを、位置引数の前、間、後ろのどこに書かれても、同じに解釈する。
4. When オプションの終端（`--`）が現れたとき, the argx ライブラリ shall その要素自体を位置引数の値とせず、それより後ろのすべての要素を、位置引数の値として扱う。
5. When オプションの終端より後ろに、もう一度 `--` が現れたとき, the argx ライブラリ shall その `--` を、位置引数の値として扱う。
6. If 位置引数の値が、現在のコマンドの位置引数が受け取れる個数を超えて現れたら, the argx ライブラリ shall 最初に超えた要素を問題の引数とする、余分な位置引数を表す解析エラーを報告する。

### Requirement 7: サブコマンド

**Objective:** As a プログラムの利用者, I want サブコマンドの名前を書いて、そのサブコマンドのオプションと引数を続けて書くこと, so that `tool remote add --force name` のような、階層のあるコマンドを使える

#### Acceptance Criteria

1. When サブコマンドを持つコマンドが現在のコマンドである間に、オプションの終端より前で、オプションではない要素が現れたとき, the argx ライブラリ shall その要素を、サブコマンドの名前として扱う。
2. When サブコマンドの名前が、現在のコマンドのサブコマンドの名前と、大文字と小文字を区別して完全に一致したとき, the argx ライブラリ shall そのサブコマンドを選び、それより後ろの要素を、そのサブコマンドを現在のコマンドとして解析する。
3. If サブコマンドの名前が、現在のコマンドのどのサブコマンドの名前とも一致しなかったら, the argx ライブラリ shall 未知のサブコマンドを表す解析エラーを報告する。
4. The argx ライブラリ shall 選ばれたサブコマンドがさらにサブコマンドを持つとき、同じ規則を繰り返し適用し、入れ子の深さを制限しない。
5. The argx ライブラリ shall オプションを、現在のコマンドの定義だけから探し、親のコマンドおよび子のコマンドのオプションを、対応づけの対象にしない。
6. If 親のコマンドにだけ定義されたオプションが、サブコマンドの名前より後ろで指定されたら, the argx ライブラリ shall 未知のオプションを表す解析エラーを報告する。
7. When サブコマンドを持つコマンドが現在のコマンドのまま、サブコマンドの名前が現れずに argv が終わったとき, the argx ライブラリ shall これを解析エラーとせず、そのコマンドを、選ばれたコマンドの並びの最後とする。
8. If サブコマンドを持つコマンドが現在のコマンドである間に、オプションの終端より後ろで要素が現れたら, the argx ライブラリ shall その要素をサブコマンドの名前として扱わず、余分な位置引数を表す解析エラーを報告する。

### Requirement 8: 値の変換

**Objective:** As a ライブラリ利用者, I want 値付きオプションと位置引数の値が、定義した値型で検査・変換されること, so that 文字列を自分で数や選択肢に変換せずに、型の付いた値を受け取れる

#### Acceptance Criteria

1. When 値付きオプションまたは位置引数に値が与えられたとき, the argx ライブラリ shall その値の文字列を、その定義要素の値型で変換する。
2. The argx ライブラリ shall 組み込みの値型と利用者定義の値型を区別せず、同じ手順で変換を求める。
3. The argx ライブラリ shall 値の文字列を、前後の空白の除去などの加工をせずに、書かれたとおりに値型へ渡す。
4. If 値型が、入力が不正であることを報告したら, the argx ライブラリ shall 値の変換の失敗を表す解析エラーを報告する。
5. If 値型が、メモリ確保の失敗を報告したら, the argx ライブラリ shall 解析エラーではなく、メモリ確保の失敗として、解析を失敗させる。
6. If 値型が、成功でも、入力の不正でも、メモリ確保の失敗でもないエラーコードを報告したら, the argx ライブラリ shall 値の変換の失敗を表す解析エラーを報告する。
7. The argx ライブラリ shall 変換に成功したすべての値を、結果が破棄されるまで（結果を渡さずに解析が失敗したときは、解析の呼び出しが戻るまで）に、その値型の後始末の手段で、ちょうど 1 回ずつ後始末する。複数回の指定で置き換えられた値、および解析が失敗するまでに変換した値を含む。

### Requirement 9: 既定値の適用と必須の検査

**Objective:** As a ライブラリ利用者, I want 指定されなかったものに既定値が入り、必須のものが欠けていればエラーになること, so that 結果を読むときに、指定の有無で場合分けをしなくて済む

#### Acceptance Criteria

1. When argv の最後まで解析エラーなしに読み終えたとき, the argx ライブラリ shall 選ばれたコマンドの並びに属する各コマンドの定義要素について、必須の検査と、既定値の適用を行う。
2. If 選ばれたコマンドの並びに属するコマンドの、必須に設定された値付きオプションが、1 回も指定されていなかったら, the argx ライブラリ shall 必須のオプションの不足を表す解析エラーを報告する。
3. If 最後に選ばれたコマンドの、必須または必須の可変個の位置引数に、値が 1 個も割り当てられていなかったら, the argx ライブラリ shall 必須の位置引数の不足を表す解析エラーを報告する。
4. When 不足している必須の定義要素が 2 つ以上あるとき, the argx ライブラリ shall 選ばれたコマンドの並びでルートに近いコマンドのものを先とし、同じコマンドの中ではオプションを位置引数より先とし、それぞれを定義した順として、最初の 1 つを報告する。
5. When 既定値を持つ値付きオプション、または既定値を持つ任意の位置引数が、指定されなかったとき, the argx ライブラリ shall その既定値を値型で変換した値を、その定義要素の値とし、値の出どころを「既定値」とする。
6. When 既定値を持たない、必須でない値付きオプション、既定値を持たない任意の位置引数、または可変個（0 個以上）の位置引数が、指定されなかったとき, the argx ライブラリ shall その定義要素を、値を持たないもの（可変個では、値が 0 個のもの）とする。
7. When フラグ、カウント、否定できるフラグが指定されなかったとき, the argx ライブラリ shall それぞれ、「指定されていない」、0 回、スキーマに設定された初期の状態を、その値とし、値の出どころを「既定値」とする。
8. The argx ライブラリ shall 選ばれたコマンドの並びに属さないコマンドの定義要素について、必須の検査も、既定値の適用も行わない。
9. The argx ライブラリ shall 値の出どころを、後のバージョンで種類（環境変数など）を足せる形で表し、初版では「コマンドライン」と「既定値」の 2 つを提供する。
10. The argx ライブラリ shall 初版では、環境変数などコマンドラインと既定値のほかの供給元から値を読む手段、およびそのための差し込み口を、公開しない。

### Requirement 10: 結果の参照

**Objective:** As a ライブラリ利用者, I want 解析の結果から、選ばれたサブコマンドと、型の付いた値を取り出すこと, so that 結果を見て処理を分岐し、値をそのまま使える

#### Acceptance Criteria

1. When 解析が成功したとき, the argx ライブラリ shall 利用者が参照して、破棄する結果を渡す。
2. The argx ライブラリ shall 結果から、選ばれたコマンドの並びを、コマンドの個数とともに、ルートコマンドから順に読み取れるようにし、最後に選ばれたコマンドを直接読み取れるようにする。
3. The argx ライブラリ shall 結果への問い合わせで、定義要素を、スキーマのオプションまたは位置引数そのもので指定できるようにする。
4. The argx ライブラリ shall フラグについて、指定されたかどうかを、カウントについて、指定された回数を、否定できるフラグについて、オンかオフかを、結果から読み取れるようにする。
5. The argx ライブラリ shall 値付きオプションと位置引数について、値を持つかどうかを読み取れるようにし、値を持つときは、値型が変換した値を、その値型の値の形式のまま（文字列、符号付き 64 ビットの整数、倍精度の浮動小数、選択肢の番号、利用者定義の値型が書き込んだ値）読み取れるようにする。
6. The argx ライブラリ shall 可変個と必須の可変個の位置引数について、割り当てられた値の個数と、それぞれの値を、argv に現れた順に読み取れるようにする。
7. The argx ライブラリ shall 選ばれたコマンドの並びに属するコマンドの、値を持つ各定義要素について、値の出どころ（「コマンドライン」または「既定値」）を読み取れるようにする。
8. When 利用者が、値を持たない値付きオプションまたは位置引数の値を求めたとき, the argx ライブラリ shall 値がないことを、値と区別できる形で報告する。
9. When 利用者が、選ばれたコマンドの並びに属さないコマンドの定義要素について問い合わせたとき, the argx ライブラリ shall これを失敗とも前提条件の違反ともせず、その定義要素を、コマンドラインで指定されていないもの（値付きオプションと位置引数では、値を持たないもの）として報告する。
10. If 解析が解析エラーで失敗したら, the argx ライブラリ shall 成功のときと同じく、利用者が参照して破棄する結果を渡し、エラーを見つけるまでに読んだ分（選ばれたコマンドの並び、指定されたフラグ、カウント、否定できるフラグ、変換に成功した値）を、成功のときと同じ方法で読み取れるようにする。
11. While 結果が解析エラーで失敗した解析のものである間, the argx ライブラリ shall 既定値を適用せず、指定されなかった値付きオプションと位置引数を、値を持たないものとして報告し、指定されなかったフラグ、カウント、否定できるフラグを、基準 9.7 の値として報告する。
12. The argx ライブラリ shall 結果が、成功した解析のものか、解析エラーで失敗した解析のものかを、結果から読み取れるようにする。
13. The argx ライブラリ shall 結果の読み取りの操作で、結果もスキーマも変更せず、メモリを確保しない。
14. The argx ライブラリ shall 結果から返す値と文字列を、結果が破棄されるまで有効で、利用者が解放する必要のないものとする。
15. The argx ライブラリ shall 結果への問い合わせのうち、プログラムの誤りでしか起こらないもの（その結果のスキーマに属さない定義要素を指定する、定義要素の種類に合わない問い合わせをする、個数の範囲を超えた番号を指定するなど）を、関数の前提条件の違反として扱う。

### Requirement 11: 解析エラーの報告

**Objective:** As a ライブラリ利用者, I want 解析エラーが、種類、問題の引数、関係する定義要素の分かる情報と、そのまま見せられるメッセージとして返ること, so that プログラムの利用者に、どの引数がなぜ駄目だったのかを、少ないコードで伝えられる

#### Acceptance Criteria

1. If 解析エラーが見つかったら, the argx ライブラリ shall その時点で解析を止め、argv の先頭から見て最初に見つけた 1 つの解析エラーだけを報告する。
2. The argx ライブラリ shall 解析エラーの種類として、少なくとも、未知のオプション、未知のサブコマンド、値の不足、値を取らないオプションに付けられた値、値の変換の失敗、必須のオプションの不足、必須の位置引数の不足、余分な位置引数、およびワイド文字の argv の不正な文字の並び（基準 12.4）を、互いに区別できる形で表す。
3. The argx ライブラリ shall 解析エラーの種類を、後のバージョンで種類を足せる形で表す。
4. When 解析エラーが報告されたとき, the argx ライブラリ shall 利用者が、エラーの種類、問題の要素の文字列、エラーの位置、現在のコマンド、関係するオプションまたは位置引数を、読み取れるようにする。
5. The argx ライブラリ shall エラーの位置を、出どころの種類と、その出どころの中での位置（コマンドラインでは、利用者が渡した argv での要素の番号）の組として表し、後のバージョンで出どころの種類を足せる形にする。
6. When 解析エラーに、問題の要素、または関係する定義要素がない（必須の不足には問題の要素がなく、未知のオプションには関係する定義要素がない、など）とき, the argx ライブラリ shall それが「ない」ことを、ある場合と区別できる形で報告する。
7. When 短いオプションの束の中の 1 文字が解析エラーの原因であるとき, the argx ライブラリ shall 束の全体である問題の要素に加えて、原因の 1 文字を、利用者が特定できるようにする。
8. When 解析エラーが報告されたとき, the argx ライブラリ shall プログラムの利用者にそのまま見せられる、英語の 1 行のメッセージを、利用者が取得できるようにする。
9. The argx ライブラリ shall メッセージに、エラーの種類ごとの説明と、プログラムの利用者が書いた問題の名前または値（未知のオプションではその名前、値の変換の失敗では値とオプションの名前または位置引数の名前、必須の不足では不足している定義要素の名前）を含める。
10. The argx ライブラリ shall メッセージを、改行を含まず、プログラム名などの接頭辞を付けない文字列とする。
11. The argx ライブラリ shall 解析エラーを、メモリ確保の失敗および成功と区別できるエラーコードで報告し、このスペックが足すエラーコードを、core-runtime のエラーコードの拡張規約に従って、既存のエラーコードの値と意味を変えずに足し、固有の空でない英語の説明文を持たせる。
12. The argx ライブラリ shall 解析エラーの情報とメッセージを、結果が破棄されるまで有効で、利用者が個別に解放する必要のないものとする。
13. The argx ライブラリ shall 呼び出し側のプログラムの誤りでしか起こらない条件（必須の引数に「ない」ことを表す値を渡す、検証を済ませていないスキーマを渡すなど）を、エラーコードで報告せず、関数の前提条件として扱い、公開関数ごとに前提条件を文書に記載する。

### Requirement 12: ワイド文字の argv

**Objective:** As a ライブラリ利用者, I want Windows で、`wmain` が受け取ったワイド文字の argv を渡して解析すること, so that ASCII 以外の文字を含む引数を、コードページによる欠落なしに受け取れる

#### Acceptance Criteria

1. Where プログラムが Windows 向けにビルドされている場合, the argx ライブラリ shall ワイド文字の argc と argv を受け取る解析の入口を提供する。
2. When 利用者がワイド文字の argv で解析を求めたとき, the argx ライブラリ shall 同じ内容を UTF-8 で表した `char` の argv を解析したときと、同じ結果または同じ解析エラーを返す。
3. When ワイド文字の argv の解析が行われたとき, the argx ライブラリ shall 結果から読み取る文字列の値、および解析エラーの問題の要素とメッセージを、UTF-8 の文字列として提供する。
4. If ワイド文字の argv の要素に、UTF-8 に変換できない並び（対になっていないサロゲートなど）が含まれていたら, the argx ライブラリ shall その要素を問題の要素とする、不正な文字の並びを表す解析エラーを報告する。
5. The argx ライブラリ shall `char` の argv の要素を、文字コードを検査も変換もせずに、バイトの並びとしてそのまま扱う。
6. The argx ライブラリ shall ワイド文字の解析の入口を Windows 以外でも提供するかどうかを設計で決め、提供する環境を文書に記載する。

### Requirement 13: メモリ、寿命、失敗時の保証

**Objective:** As a ライブラリ利用者, I want 解析が途中で失敗しても、メモリが漏れず、何を破棄すればよいかが決まっていること, so that 戻り値を検査して後始末するだけで、安全にプログラムを終了または続行できる

#### Acceptance Criteria

1. The argx ライブラリ shall 解析と結果のためのすべてのメモリを、ライブラリ全体に設定されたアロケータから確保し、解析の関数の引数としてアロケータを受け取らない。
2. If 解析の途中でメモリ確保が失敗したら, the argx ライブラリ shall メモリ確保の失敗を表すエラーコードを返し、その解析のために確保したメモリと、変換した値を、利用者に破棄を求めずに、すべて後始末する。
3. If 解析の呼び出しが失敗したら, the argx ライブラリ shall 結果を受け取る先として渡された場所を、文書に記載した決まった状態にしておく。
4. When 利用者が結果の破棄を求めたとき, the argx ライブラリ shall その解析のために確保したメモリを 1 つも残さず、スキーマと値型を変更も破棄もしない。
5. When 利用者が、破棄の関数に「オブジェクトがない」ことを表す値を渡したとき, the argx ライブラリ shall 何もせずに戻る。
6. The argx ライブラリ shall 結果を、スキーマより先に破棄するものとし、結果が存在する間にスキーマを変更または破棄しないことを、利用者の守る条件として文書に記載する。
7. The argx ライブラリ shall 結果が argv の文字列を複製するか借りるかを、所有権と寿命の規約に沿って設計で決め、借りる場合は、利用者が argv の文字列を有効に保つ期間を文書に記載する。
8. The argx ライブラリ shall このスペックの範囲で、変更可能なグローバル状態を持たない。
9. The ArgX リポジトリ shall 解析の関数について、メモリ確保の各回を順に失敗させても、メモリの漏れがなく、変換した値の後始末が漏れず、スキーマが使用と破棄のできる状態に保たれることを、自動のテストで確かめる。

### Requirement 14: 公開インターフェースの互換性と独立性

**Objective:** As a ライブラリ利用者, I want 解析と結果の API が、後のバージョンでも壊れず、どの環境でも同じに動くこと, so that 動的ライブラリを差し替えても、自分のプログラムをビルドし直さずに使い続けられる

#### Acceptance Criteria

1. The argx ライブラリ shall 結果と解析エラーの情報を、構造体の中身を利用者に公開しない形で提供し、後のバージョンで機能を足しても、既存の利用者のプログラムを再ビルドなしで動作させ続けられるようにする。
2. The argx ライブラリ shall このスペックが公開する関数、型、マクロのすべてを、`<argx/argx.h>` を取り込むだけで使えるようにする。
3. The argx ライブラリ shall このスペックが公開する関数と型のすべてに接頭辞 `argx_` を、マクロと列挙の定数のすべてに接頭辞 `ARGX_` を付ける。
4. The argx ライブラリ shall このスペックが公開する関数を、静的ライブラリと動的ライブラリのどちらでも、Linux・macOS・Windows のいずれでも、同じ argv に同じ結果を返すものとする。ワイド文字の入口は、それを提供する環境に限る。
5. The argx ライブラリ shall このスペックの範囲では、実行時に C 標準ライブラリ以外へ依存せず、C99 の範囲で、コンパイラ独自の拡張を使わずに実装される。
6. The argx ライブラリ shall 解析と結果の参照を、ヘルプの文面の生成の機能に依存せずに使えるものとする。
7. The ArgX リポジトリ shall このスペックの公開関数の使い方（スキーマの検証から、解析、結果の参照、解析エラーの表示、破棄までの一連の例と、このスペックが定める引数の書き方の一覧を含む）を、リポジトリ内の文書に記載する。
