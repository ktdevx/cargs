# Implementation Plan

新しいソースまたはテストを作るタスクは、ライブラリのソース一覧またはテストの登録に 1 行足す。ほかのタスクも、同じソース、公開ヘッダ、テストに追記する。同じファイルを触るので、並行させず、番号の順に行う（`(P)` を付けていない）。公開関数の宣言は、その関数を実装するタスクの中で公開ヘッダに足す。宣言だけを先に足すと、動的の構成の export の確認が失敗するためである。確保を伴うテストは、テストの登録にテスト用アロケータのソースを足し、テスト用アロケータを設定して行う。

  - エラーコードの一覧の末尾に、不正な名前、名前の衝突、定義の矛盾、不正な既定値、不正な値の 5 つを、設計の Error Handling の表の順と説明文で足す。既存の行は変えない
  - 所有権の規約の「実行時の失敗とプログラムの誤り」に、文字列の内容と定義どうしの関係に由来する誤りはエラーコードで返し、空のポインタ、範囲外の添字、列挙にない値は前提条件のままにする、という分け方と理由を足す

  - 完了の目安: 既存のエラーコードのテストが、足した 5 つについても、説明文が空でなく互いに異なることを確かめて通る。既存の 2 つの値（0 と 1）は変わらない

- [x] 2. 状態を持たない部品
- [x] 2.1 名前の規則を判定する内部関数を作る
  - 短い名前（ASCII の英字または数字の 1 文字）、長い名前（2 文字以上で、英字または数字で始まり、英字、数字、`-`、`_` だけ）、サブコマンド名（1 文字以上で、長い名前と同じ文字の規則）を判定する 3 つの内部関数を作る
  - 文字の判定は、ロケールに左右される標準の文字分類を使わず、ASCII の範囲の比較で書く。確保をしない

- [x] 2.2 整数と浮動小数の変換をする内部関数を作る
  - 整数は自前で読む。符号を先頭に付けてもよい 10 進の数字の並びだけを受け付け、桁あふれを先に検査しながら積み上げる。符号付き 64 ビットの最小値と最大値を受け付け、それを超える値、空、符号だけ、空白、ほかの文字を拒む
  - 浮動小数は、先に形（符号、数字、`.`、指数）を自前で検査し、空白、無限大と非数の表記、16 進の表記、`,` を拒む。通った入力は、`.` を現在のロケールの小数点の文字列に置き換えた複製にしてから、標準の変換関数に渡す。小数点の文字列は、数値を整形した結果から得る
  - 複製は、短い入力では関数の中の固定長の配列に、収まらない入力では内部のメモリ関数で確保した領域に作り、戻る前に解放する。結果が無限大なら範囲外として失敗にする。`errno` を呼び出しの前の値に戻す
  - 成功したら値を書いて成功を返す。入力が不正なら不正な値のエラーコード、複製の確保に失敗したらメモリ確保の失敗を返し、出力先を変えない
  - 内部関数のテストを足す。設計の Testing Strategy の `number_test.c` の項目（整数と浮動小数の境界、小数点が `,` のロケールへの切り替えを試みる確認と C ロケールでの確認、長い入力での確保の失敗、`errno` が変わらないこと）を確かめる。ロケールを切り替えられない環境でも、アサーションが必ず 1 つ以上実行されるように書く
  - 完了の目安: 静的と動的の両方の構成で数値の変換のテストが通り、未解放の個数と契約違反の回数が 0 で、確保関数の検査が通る
  - _Boundary: Number_
  - _Requirements: 6.3, 6.4, 6.5, 6.6, 6.7, 12.5_

- [x] 3. 値型
- [x] 3.1 値型の公開ヘッダと、文字列・整数・浮動小数の組み込みの値型を作る

  - 型の名前、種類、値の大きさを読み取る公開関数と、変換を求める公開関数、後始末を求める公開関数を作る。変換は、種類で分岐せず、値型が持つ変換関数を呼んで、その戻り値をそのまま返す。後始末は、後始末関数があれば呼び、なければ何もしない
  - 文字列の変換は必ず成功し、値として入力の文字列へのポインタを書く。整数と浮動小数の変換は 2.2 の内部関数を呼ぶ
  - ヘッダのコメントに、変換の契約（領域の大きさと整列、成功したら後始末を 1 度呼ぶこと、失敗したら呼ばないこと、値が入力の文字列を参照してよいこと）、種類と値の型の対応、関数ごとの前提条件を書く
  - 公開 API のテストを足す。3 つの型の名前、種類、値の大きさ。同じ関数を 2 回呼ぶと同じポインタが返ること。空の文字列を含む文字列の変換と、値が入力のポインタであること。整数と浮動小数の代表的な成功と失敗
  - 完了の目安: 静的と動的の両方の構成で値型のテストが通り、動的の構成の export の確認が、このタスクで宣言した関数だけを新しい公開関数として認める

  - 選択肢の変換は、大文字と小文字を区別して完全に一致する選択肢を探し、値として一致した選択肢の番号を書く。一致しなければ不正な値のエラーコードを返す
  - 選択肢の個数と、番号で選択肢を読む公開関数を作る。一覧は定義した順に読める。選択肢でない値型では個数は 0 である
  - 値型を破棄する公開関数を作る。空のポインタと、組み込みの値型には何もしない
  - 生成の途中で確保に失敗したら、その呼び出しの確保をすべて解放し、出力先を空のポインタにして、メモリ確保の失敗を返す

  - 完了の目安: 静的と動的の両方の構成で、選択肢を含む値型のテストが通り、未解放の個数と契約違反の回数が 0 である

- [ ] 4. スキーマの定義
- [x] 4.1 コマンドの木（生成、サブコマンド、破棄、説明文、読み取り）を作る
  - スキーマの公開ヘッダを新しく作り、コマンド、オプション、位置引数の不透明な型と、オプションの種類、位置引数の個数の種類の列挙を置いて、入口のヘッダから取り込む。内部ヘッダに、コマンド、オプション、位置引数の 3 つの構造体を、設計の Logical Data Model のとおりに全部定義する

  - サブコマンドを足す公開関数を作る。順に検査する: 名前が規則に合わなければ不正な名前、足す先のコマンドが位置引数を持てば定義の矛盾、同じ名前のサブコマンドがあれば名前の衝突。入れ子の深さは制限しない
  - ルートを破棄する公開関数を作る。サブコマンドを再帰的にたどり、オプション、位置引数、複製した文字列、配列、コマンド自身を解放する。値型は解放しない。空のポインタには何もしない

  - 定義要素に共通の内部の補助関数を作る: 木のルートを返す、木を未検証にする、文字列を複製して古いものと入れ替える（失敗したら元のまま）

  - 完了の目安: 静的と動的の両方の構成でコマンドのテストが通り、未解放の個数と契約違反の回数が 0 で、動的の構成の export の確認が通る

## Implementation Notes

- 3.3: `struct clargs_type` に、設計の Logical Data Model にない `char *owned_name` がある（利用者定義の値型だけが持つ、複製した型の名前。破棄で `const` を外さずに解放するため）。構造体は非公開で、設計の欄はそのまま残る。
- 3.x: 生成の関数は、先頭で `*out = NULL` にし、検査をすべて確保より前に行う。テストは、確保を伴うものを `check_clean()`（未解放 0、契約違反 0）で終え、定数の条件の検査の代わりに `NAOS_FAIL` を使う（MSVC の C4127 を避ける）。
- 4.1: `clargs_command_find_short()` は `'\0'` に必ず `NULL` を返す（短い名前のないオプションは `'\0'` で持つ）。`<clargs/schema.h>` は、値型を使う宣言を足すタスク（4.2）で `<clargs/type.h>` を取り込む。オプションと位置引数が入った状態の列挙、検索、破棄は、4.2 と 4.4 のテストで公開 API から確かめる。
- 4.2: 検査の表の 6 行目（否定名の衝突）は、`clargs_command_find_long()` でなく、オプションの列挙で同じ比較をする（`src/option.c` の `negated_name_is_in_use()`）。`no-<名前>` を作るには確保が要り、検査を確保より前に行う設計の順序を保てないためである。
- 4.2: 「追加が成功したら木を未検証にする」は実装済みだが、公開の読み取りがないので、表明は 5.1 のテストで行う。`src/option.c` の `free_new_option()` は `long_name` と `negated_name` だけを解放する（追加の直後は、ほかの文字列は必ず `NULL`）。
- 4.3: `<clargs/schema.h>` のオプションの文字列の設定の Preconditions に、設計にない 1 文（今その属性として持っている文字列やその一部を渡さない）がある。実装は複製してから解放するので不要で、`clargs_command_set_description()` のコメントとも食い違う。6.2 のヘッダのコメントの点検で消す。位置引数の設定（4.4）には書かない。
