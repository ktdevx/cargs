# Brief: command-schema

## Problem

C のアプリケーション開発者は、自分のプログラムが受け付けるコマンドラインを定義したい。短い名前と長い名前、オンとオフを切り替えるフラグ、`--no-<name>` での否定、`-vvv` のように回数を数えるオプション、値を取るオプション、位置引数、サブコマンドがある。これを `getopt` と手書きの分岐で書くと、定義が解析のコードに散らばり、名前の重複などの誤りに実行時まで気づけない。

ライブラリの側では、定義を解析やヘルプ生成から切り離しておかないと、どちらかを変えるたびにもう一方も触ることになる。

## Current State

core-runtime が、アロケータ、状態コード、所有権の規約を用意している。コマンドラインを表すものはまだない。

## Desired Outcome

- 利用者は、関数呼び出しで、ルートコマンド、サブコマンド（入れ子も）、オプション、位置引数を定義できる。
- オプションには、短い名前、長い名前、またはその両方を付けられる。
- オプションの種類として、フラグ、否定できるフラグ、カウント、値付きを選べる。
- 値付きオプションと位置引数には値型を指定できる。文字列、整数、浮動小数、選択肢が組み込みで使え、利用者が自分の型を足せる。
- 説明文、値の表示名、必須かどうか、既定値などの属性を付けられる。
- 定義の誤り（同じコマンド内での名前の重複、不正な名前、否定名との衝突など）は、定義した時点または検証の時点でエラーになる。
- 定義したスキーマは、読み取り用のインターフェースで調べられる。argv-parser と help-formatter はこれだけを使う。
- スキーマは argv をまったく知らない。

## Approach

不透明ハンドルとビルダー関数で定義する。ルートコマンドを作るときにアロケータを渡し、その木に属するものはすべて同じアロケータを使う。木全体はルートが所有し、ルートを破棄すると全部が解放される。

属性は、設定関数を足していく形にする。構造体を公開しないので、後から属性を足しても ABI を壊さない。

値型は、名前と変換関数の組として表し、組み込みの型も同じ仕組みに載せる。これが拡張点になる。変換関数を「いつ呼ぶか」は argv-parser が決め、このスペックは「何であるか」だけを持つ。

読み取り用のインターフェースは、内部向けに必ず用意する。どこまでを公開 API にするかは設計で決める。

## Scope

- **In**:
  - コマンドの生成と破棄、サブコマンドの追加（入れ子）
  - オプションの追加（フラグ、否定できるフラグ、カウント、値付き）と、短い名前・長い名前
  - 位置引数の定義（必須、任意、可変個）
  - 属性（説明文、値の表示名、必須、既定値など）
  - 値型（文字列、整数、浮動小数、選択肢）と、利用者定義の値型の拡張点
  - 定義の検証（重複、不正な名前、`--no-<name>` と既存の名前の衝突、位置引数の並びの矛盾）
  - スキーマの読み取りインターフェース（コマンド、オプション、位置引数、サブコマンドの列挙と属性の取得）
- **Out**:
  - argv の解析、結果の保持
  - ヘルプや usage の文面
  - オプション同士の関係の制約（排他、依存）。将来の拡張とする
  - 環境変数や設定ファイルとの対応付け
  - 長いオプション名の省略、別名（エイリアス）

## Boundary Candidates

- コマンドの木（コマンドとサブコマンド）
- オプションの定義（種類と名前）
- 位置引数の定義
- 値型（組み込みと拡張点）
- 定義の検証
- 読み取りインターフェース

## Out of Boundary

- 変換関数を呼ぶ時機と、変換した値の保持（argv-parser）
- 定義から文面を作ること（help-formatter）
- アロケータと状態コードの仕組み（core-runtime）
- 解析時のエラー（未知のオプション、値の不足など）の表現（argv-parser）

## Upstream / Downstream

- **Upstream**: core-runtime（アロケータ、状態コード、所有権の規約、内部ユーティリティ、テスト用アロケータ）
- **Downstream**: argv-parser（スキーマを読んで解析する）、help-formatter（スキーマを読んで文面を作る）

## Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**:
  - argv-parser: 値型のインターフェースと、スキーマの読み取りインターフェースを共有する。解析の文法（`-abc` の束ね方など）はここで決めない。
  - help-formatter: 説明文などの表示用の属性はここで持つが、整形はしない。

## Constraints

- C99。公開構造体を ABI にしない（不透明ハンドル）。
- すべてのメモリ確保は core-runtime のアロケータを通す。確保の失敗はエラーとして返す。
- 変更可能なグローバル状態を持たない。組み込みの値型もグローバルな登録表に頼らない。
- 短い名前は 1 文字、長い名前は ASCII の範囲で規則を決める（要件で確定）。
- 浮動小数の変換はロケールの影響を受けうる。扱いを設計で決める。
- 公開名は `roadmap.md` の Naming に従う（ライブラリ名 `clargs`、ヘッダ `<clargs/clargs.h>`、接頭辞 `clargs_` / `CLARGS_`）。
