# Brief: core-runtime

## Problem

ライブラリの利用者には、メモリ確保を自分のアロケータに差し替えたい場面がある（組み込み、アリーナ、メモリ使用量の追跡、確保失敗のテスト）。ライブラリが `malloc` を直接呼ぶと、それができない。

また、失敗をどう伝えるかがスペックごとに違うと、利用者は関数ごとに作法を覚えることになり、ライブラリの開発者も境界をまたぐたびに変換を書くことになる。

## Current State

build-foundation が、ビルド、配布、テスト基盤、命名規約を用意している。メモリ確保とエラー報告の共通の仕組みはまだない。

## Desired Outcome

- 利用者は、確保・ゼロで初期化する確保・再確保・解放の関数をライブラリ全体に 1 つ設定して、ライブラリのメモリ確保をすべて差し替えられる。何も設定しなければ標準の `malloc` 系を使う。
- ライブラリのどのコードも、この仕組みを通さずにメモリを確保しない。
- すべての公開関数が、同じ形で成功と失敗を返す。失敗の種類はコードで区別でき、コードから説明文を得られる。
- メモリ確保の失敗は、クラッシュや中断ではなく、エラーとして呼び出し元に返る。
- 誰が確保し誰が解放するかの規約が文書になっていて、後続のスペックが従える。
- 後続のスペックは、確保の失敗を注入できるテスト用のアロケータを使って、失敗時の挙動をテストできる。

## Approach

アロケータは、標準の `malloc`、`realloc`、`calloc`、`free` と同じ形の関数ポインタ 4 つをまとめた小さな値として、設定関数でライブラリ全体に 1 つ設定する。利用者のデータ（コンテキスト）は持たない。こうすると、標準の関数や既存の確保ライブラリをそのまま設定でき、公開関数にアロケータの引数が要らない。変更可能なグローバル状態は、この設定だけに限る。設定は同期しないので、ライブラリのオブジェクトが 1 つもなく、ほかのスレッドがライブラリを呼んでいないときに行う決まりにする。

エラーは、戻り値のエラーコードで返す。`errno` も `abort` も使わない。コードの集合は後から足せる形にし、各スペックが自分のコードをどう足すかをここで決める。

文字列の複製や伸長する配列など、後続のスペックが共通して必要とする内部ユーティリティは、アロケータの上に用意する。これらは公開しない。

## Scope

- **In**:
  - アロケータの公開インターフェース（確保、ゼロで初期化する確保、再確保、解放の関数と、それをライブラリ全体に設定する関数）と、既定のアロケータ
  - ライブラリ内部からアロケータを使うための内部 API
  - エラーコードの型、コードから説明文を得る関数、コードの足し方の規約
  - 所有権と寿命の規約（生成と破棄の対、文字列の扱い、`NULL` の扱い）
  - 内部ユーティリティ（文字列の複製、伸長する配列など、必要最小限）
  - テスト用の失敗注入アロケータ（N 回目の確保を失敗させる、解放漏れを数える）
- **Out**:
  - コマンドライン固有の概念（オプション、コマンド、argv）
  - 解析エラーの詳細（どの引数で失敗したか）の表現
  - ログ出力、アサーションのフック
  - スレッド同期の仕組み（アロケータの設定は、利用者が決められた時点で行う）
  - メモリプールやアリーナの実装（利用者が差し替えで持ち込む）

## Boundary Candidates

- アロケータ（公開インターフェースと既定の実装）
- エラーモデル（エラーコードと説明文）
- 内部ユーティリティ（アロケータの上のデータ構造）
- テスト支援（失敗注入アロケータ）

## Out of Boundary

- スキーマや結果オブジェクトの生成と破棄（command-schema、argv-parser がこの規約に従って実装する）
- 利用者向けのエラーメッセージの整形（argv-parser、help-formatter）
- ビルド設定や export マクロの定義（build-foundation）

## Upstream / Downstream

- **Upstream**: build-foundation（ビルド、命名規約、export マクロ、テストの登録方法）
- **Downstream**: command-schema、argv-parser、help-formatter。すべてのメモリ確保とエラー報告がここを通る。

## Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**: build-foundation（公開ヘッダの置き方に従う）、command-schema（最初の利用者。所有権の規約を実際に適用する）

## Constraints

- C99。実行時の依存は C 標準ライブラリのみ。
- 変更可能なグローバル状態は、設定されたアロケータだけとする。
- 公開する型は、後からフィールドを足しても ABI を壊さない形にする。アロケータの構造体の将来の拡張方法を設計で決める。
- ライブラリが確保したメモリを利用者に解放させず、利用者が確保したメモリをライブラリが解放しない。
- 公開名は `roadmap.md` の Naming に従う（ライブラリ名 `argx`、ヘッダ `<argx/argx.h>`、接頭辞 `argx_` / `ARGX_`）。
