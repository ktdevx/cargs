## Implementation Notes

- MSVC の DLL ランタイムでは、標準の関数（`malloc` など）は import される。そのアドレスを静的な初期化子に書けず、`/W4` では局所の初期化子や代入でも警告（C4204、C4232）になる。ライブラリのソースでは `static` 関数で包み、標準の関数をそのまま並べるテストでは、ファイルの先頭で `#ifdef _MSC_VER` の `#pragma warning(disable : 4204 4232)` を書く。
- テストでは、初期化子のない `const` オブジェクトを書かない（MSVC の `/W4` で C4132 になる）。`= { 0 }` を付ける。
- テストから、標準の確保関数へ巨大な大きさを実際に渡さない（ASan と valgrind が異常終了する）。引数を記録して `NULL` を返すだけのアロケータを設定して確かめる。
- 桁あふれの検査のテストは、あふれる側と、ちょうど収まる側の両方を確かめる。ちょうど収まる側は、テスト用アロケータで 1 回目の要求を失敗させ、要求の回数が 1 であることで「アロケータまで届いた」ことを確かめる（巨大な大きさを標準の確保関数へ渡さない）。
- 文書に載せる C の例は、取り出してそのままコンパイルできる形で書く（宣言している公開ヘッダを取り込む）。仮の名前を使う例は、仮のヘッダの内容をコメントに書く。
- `destroy` に `NULL` を渡すと何もしない、という規約は、`create` で生成したオブジェクトの話である。呼び出し側が持つ構造体（`clargs_vec_t`）の `clargs_vec_destroy` は、`NULL` を前提条件の違反とする。
